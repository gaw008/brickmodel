# Depletion integration pre-registration

The first implementation retains normal SSPRK2 safe panels, then an explicit Euler terminal event panel with actual complete Rates/positive evaporation diagnostics. It selects a directed representable time not later than the rational Nl/−netNl event. No clipping or ordinary wet evaluation at zero liquid is allowed. Positive numerical phase correction and binary64 storage rounding use the existing bounded depletion_roundoff helper and distinct ledgers.

Acceptance requires two consecutive coarse/fine event comparisons and actual dry continuation to the same preselected local common time min(next program node, end, start + max(common_time_horizon_s, 2*terminal_window_s)). Compare event times, all event/continuation amounts/U and decoded T/P; these are refinement indicators, not rigorous ODE error bounds. Every subpanel stays before the next program node; another unseparated event is unsupported. Global stored-binary64 face/source/work ledgers and event corrections are accumulated with Fraction across every accepted segment, never reset at events.

Oracle gates fixed before execution: constant sink N0=1e-4mol,r=1e-3mol/s,t*=.1s,end=.2s: event error≤1e-9s, global water≤1e-12mol,U≤1e-8J. Linear time sink a=1e-3,b=2e-3 mol/s² uses independent quadratic event root, error≤1e-7s; common final-time amounts≤1e-11mol,U≤1e-7J,T≤1e-5K. Exact dry heating oracle uses U/Cv, not a fake water provider. Roundoff policy supplied explicitly with correction fraction≤1e-8 and independent local/cumulative storage/element/mass limits. Resource limits remain supplied IntegrationPolicy wall/steps/rejections plus finite event refinement budget; cancellation preserves the last committed valid state.

Clock refinement pre-registration (after two recorded RED oracle failures): binary64 absolute event time has its own spacing, independent of terminal inventory spacing. A new immutable clock evidence object must reconstruct the exact rational proposed root from original panel inventory and signed liquid Rates, require the actual endpoint to be its nearest downward float, and validate every stored liquid panel term against the same exact endpoint difference. Only the derived |net liquid rate|*(exact root−actual endpoint) may supplement the existing local inventory ULP limit; it remains a numerical paired projection, not physical evaporation. All existing absolute, gross-positive-evaporation-relative and cumulative correction/storage/element/mass budgets remain. Every face/source/work and gross evaporation integral uses that exact rational endpoint interval followed by one binary64 rounding. No field uses a different effective duration.

## Public API and accounting

`integrate_depletion(initial, operator, start_s=..., end_s=..., integration_policy=..., event_policy=..., cancel=None)` accepts the explicit `WaterPhaseTransfer` host or `ManufacturedDepletionAdapter`. The latter is classified `manufactured_numerical_oracle_not_material`; it supplies complete `Rates`, genuine oracle evaporation diagnostics, and independent T/P observations with declared observation error budgets. It does not replace any water EOS or confer material qualification. Real-host roundoff molar mass must equal the chemical model reference mass.

`DepletionPolicy` requires `time_absolute_s`, `amount_absolute_mol`, `energy_absolute_j`, `temperature_absolute_k`, `pressure_absolute_pa`, `terminal_window_s`, `maximum_refinements`, and `roundoff_policy`; `common_time_horizon_s` defaults to 0.01 s. All tolerances have the named SI units. The local common time is fixed before refinement. Two consecutive adjacent-level comparisons must pass; the terminal panel is first order, so no SSPRK2 Richardson division by three is applied. Comparisons include both unequal-time event-face states and independently evolved common-time states, all inventory columns, total U, and T/P plus the supplied observation uncertainty. These are numerical refinement indicators, not a rigorous continuous ODE error certificate.

Wet proposal caps halve at each level. Dry continuation separately uses the unchanged ordinary integration maximum step and adaptive error policy, rather than exponentially shrinking its step with the terminal event cap. Both candidates still actually run to the same common time with complete heat/transport/reaction evaluations. Ordinary continuation accuracy is controlled by its separately supplied policy; if its numerical error floor prevents event comparisons from passing, the result fails rather than enlarging the event tolerance. This is not a uniform-step whole-trajectory convergence claim.

The result retains all accepted `times_s`, immutable `states`, and original `StepLedger` objects in `steps`. Each event retains its terminal physical panel, exact clock gap, positive gross evaporated amount, numerical paired correction and binary64 storage-rounding record, comparison differences, and own/coarse/previous/common times. The physical panel uses the actual exact interval between stored binary64 endpoints for every face/source/work term, rounded once per stored integral. Its paired numerical projection is separate from physical reaction-source ledger terms. Consumers reconstruct the accepted trajectory using physical panels **plus** the explicitly recorded correction: liquid −δ; vapor +δ plus its separately recorded storage write-back residual; U unchanged. Formation energy is already in U; no artificial latent-heat source is added.

`cumulative_amounts_mol` and `cumulative_energy_j` are exact `Fraction` sums of stored physical panel terms and accepted corrections from the original initial state. They are never reset at an event or continuation boundary. Ordinary state-write arithmetic is checked against the original integration amount/U tolerance; event storage/element/mass and paired numerical correction additionally obey their separate local and cumulative budgets. `roundoff_totals` remains available for audit. An exact-zero terminal event has no nonzero correction record; it still records the event and changes the interface mode.

`result.refinements` retains each attempted level's start, cap, fixed common time, event time where available, five comparison differences (time, amount, energy, temperature, pressure), status, evaluations and elapsed seconds. Failed previews are discarded transactionally: neither interface mode, stored state, accepted event list nor cumulative correction prefix is changed. The result gives the last committed valid state with an explicit failure/resource/cancellation status.

`IntegrationPolicy.maximum_steps` bounds accepted trial panels, including panels on subsequently discarded refinement proposals; `result.accepted_trial_panels` gives this count (`attempted_steps` is its retained legacy field name). This is not a count of all adaptive trials. `maximum_rejections` independently bounds cumulative rejected ordinary adaptive trials. The remaining global wall-clock budget and cancellation callback pass to every ordinary integration call. Terminal panels and observations also check global limits. These are synchronous checks at solver boundaries, not interruption of a running EOS function.

## Supported boundary and tests

The validated numerical oracles cover one evaporating cell, a constant sink, a linearly time-dependent sink with an intervening program node, actual dry heating, exact event/node coincidence rejection, cancelled/resource-limited speculative previews, simultaneous-cell rejection, non-evaporative liquid-loss rejection, and distinct paired versus storage correction with an initial 0.1 mol vapor inventory. A dry-only oracle checks preservation of external heat rates but is not the wet-to-dry completion evidence. The two wet oracles are that evidence.

The implementation retains shared face arrays and full inventory layout. It has not independently verified a multi-cell sequence of depletion events or general stiff/cyclic reaction topology. Simultaneous or insufficiently separated competing events, a second locally predicted event inside a preview horizon, and an event too close to the program node/end to establish ordering are explicit unsupported exits. It neither invents nucleation after depletion nor automatically coalesces an event with a furnace-program node. Dry constitutive behavior remains the selected WaterPhaseTransfer strict/metastable policy.

The initial two clock failures are preserved in `research/depletion_clock_initial_failure.json`. A proposed repeated-start workaround was tested only in memory and rejected after it reached unresolvable stage times. The clock evidence extension resolved the actual issue without changing the pre-registered analytic tolerances. After extension, 29 lightweight tests passed (16 original roundoff, 4 clock, 9 event); the subsequently added independent 0.1 mol vapor prefix case passed with the other 9 event tests (10 total). Actual source-gated wet-host validation is separately recorded by the root run and is not inferred from these manufactured oracles.

The independent reviewer subsequently ran the final lightweight set: **30 passed in 0.33 s** (16 original roundoff + 4 clock + 10 event). This supersedes the earlier 29-count snapshot, without changing any tolerance. The first full source-gated host attempt separately hit the 120 s wall limit before accepting an event; that attempt used terminal-cap-limited dry previews. Its failure is retained by the root rather than described as successful continuation.

A subsequent real-host diagnostic showed that the first two proposals could use an identical terminal panel when entering tau was smaller than the configured window. A new independently analytic time-varying oracle (Nl=1e-8 mol, a=.001 mol/s, b=2 mol/s²) first failed: the falsely accepted identical Euler panels had an event-time error of 9.804864072151452e-8 s against the 1e-8 s requirement. The initial cap is now `min(terminal_window_s, entering_tau)`, and subsequent caps halve from that value. The regression checks both the independent event root and the actual accepted terminal duration, not merely the configured cap. After this repair the complete lightweight set is **31 passed in 0.38 s**. The earlier 30-pass result remains historical evidence and did not cover this defect.

The root's third full source-gated host attempt completed with unchanged source/test dependencies: **86.82 s, 224 evaluations, 27 accepted trial panels, 0 rejections, 21 stored states**. It located the actual liquid-depletion event at **0.00028422061165952946 s** and continued to **0.03125 s**. The independently reconstructed full water/element/mass and energy-prefix ledgers, boundary heat checks, and post-depletion warming interval assertions passed. The numerical terminal window was tightened from 1/1024 s to 1/16384 s before this attempt; the original time/U comparison gates, common-time horizon and 120 s wall limit were not loosened. Earlier attempts remain saved failures. This validates the specified manufactured geometry/coefficient scenario with actual water properties, not sludge material parameters or a complete kiln process.

Subsequent numerical-control extension: `DepletionPolicy.safe_inventory_fraction` (default .25, strict 0<f<.5) now explicitly controls all three ordinary inventory-based step caps and is retained in the result. If and only if all interfaces are dry, ordinary integration proceeds continuously to the next node/end, preserving adaptive history. This intentionally changes dry time grids; no overall default-bitwise-equivalence claim applies to this combined revision. See `DEPLETION_SAFE_FRACTION.md` for the prior isolated-patch comparison, actual dry-restart RED evidence, unchanged accuracy/resource constraints, and 55-test validation.
