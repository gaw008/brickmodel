# 固液气统一储能与含载气水汽耦合设计

状态：实现提案，不是完成证明。依据当前 `water_properties.py`、`thermochemistry.py`、`gas_heat_model.py` 和 `WORLD_SPEC.md`。当前纯水适配器已独立复验，但尚未接入含液体的库存、几何和总能量反演。本设计保持完整湿坯—烧结目标；以下顺序是实现依赖，不是削减完成条件。

## 1. 必须分开的三个接口

当前 `CaloricSpecies` 是仅依赖 T 的理想气体协议；液态水的 u、密度与压力有关，不能通过添加一个 `H2O_liquid` 名称便获得正确接口。建议新增独立 multiphase namespace，先保留现有气体验证模型不变。

| 接口 | 输入 | 输出及约束 |
|---|---|---|
| `PhaseProperties.evaluate` | species/phase ID、T、必要的 p 或 rho，以及模型版本 | u、h、s（若已批准）、摩尔体积、热力学导数、有效域、引用和参考态 ID；每项声明单位和自变量约束 |
| `CellClosure.evaluate_at_temperature` | 每相实际 mol 库存、当前几何/闭孔/力学变量、T、明确的机械闭合 | 相体积、气孔体积、气体总压和分压、液压力、各相能量、弹性/界面储能和闭合残差 |
| `CellStorage.decode` | 上述库存、几何/内部变量、总 U、温区和数值政策 | 同一个温度及完整闭合状态，或明确的缺证据、域外、非唯一、数值失败 |

源接口不允许“缺参数时取 0”。固体伪组分必须显式给组成、物质的量定义、分子量、u/h 与参考态；每公斤材料热容不能在不知道基准的情况下换成 mol。真实原泥组分仍需证据包批准。

返回数据使用不可变对象。实际 mol/J 是求解器的广延库存基准，与当前 WORLD_SPEC 一致；参考体积浓度只由显式 V0 派生，不作为可直接累加的状态。

## 2. 统一能量与压力闭合

每个单元：

```text
U = sum_s N_s u_s(T, mechanical_state)
  + N_liq u_liq(T,p_liq)
  + sum_g N_g u_g(T)
  + E_elastic + E_interface

V_gas = V_current - V_solid - V_closed - V_liquid
V_liquid = N_liq v_liq(T,p_liq)
P_gas = R_mix T sum_g N_g / V_gas
p_g,k = P_gas N_g,k / sum_g N_g
```

这里 `P_gas` 是理想混合气模型定义，不是纯水 EOS 输出。液体压力 `p_liq` 不是水汽分压。平界面纯水/气体、无毛细应力的验证容器可明确采用 `p_liq=P_gas`；砖孔必须给有证据的毛细/力学关系，例如定义清楚符号的 `P_gas-p_liq=p_cap`。没有该材料关系不能默认平界面。

液体体积影响 V_gas，P_gas 又影响液体密度。因此 `evaluate_at_temperature` 对活跃液体求自洽的机械/体积闭合；不能先固定液体饱和密度再计算压力。`N_liq=0` 时完全跳过液体物性查询，使已干单元可以进入更高温；不应用零库存物种的温区限制活跃物种。气孔为零或负、无气体却调用理想混合气分率、找不到稳定液态压力解等分别退出。

T 反演必须沿这一闭合路径重新求压力和相体积。导数 `dU/dT` 包含 `∂u_liq/∂p · dp_liq/dT`、几何或力学约束贡献，通常不等于简单的 `sum N Cv`。先用有括区的能量求根和独立残差检查；热容只作已证明安全的加速/单调性诊断。存在多根或物性接缝时不能任取一根。

运输能量保持当前单面一次账本：导热 + 每个气体的摩尔焓通量 + 液态摩尔焓通量；库存反应/相变不再额外加相同反应热或潜热。当前刚性容器可明确不含外边界移动功；形变砖仍须接入世界规范的应力功、弹性和界面能，不能将此阶段的刚性简化延伸成完整砖模型。

## 3. IAPWS 与含载气模型：显式派生桥，绝不修改原方程

固定纯水包内部保持 `R95=461.51805 J/(kg K)`、`M95=0.018015268 kg/mol`，原生摩尔常数 `R95_m=8.314371357587 J/(mol K)`。现有气体模型使用 `R_mix=8.31446261815324`。当前严格常数一致性检查应继续生效。[IAPWS 官方发布页](https://iapws.org/technical-guidance/release/IAPWS-95)与缓存 PDF 印刷 p3 Eqs. 1–3、p11 Table 3 支持固定常数与导数关系。

可独立实现 `DerivedIdealWaterVapor`，它是一个新的、明确标记的理想混合气热量模型，而不是声称原始 IAPWS 气体已经采用 R_mix：

```text
h_v,bridge(T) = h_v,95,ideal(T) + C_E       # 使用摩尔量
Cp_v,bridge(T) = Cp_v,95,ideal(T)
u_v,bridge(T) = h_v,bridge(T) - R_mix T
Cv_v,bridge(T) = Cp_v,bridge(T) - R_mix
Delta_u_vs_aligned_95 = -(R_mix-R95_m) T
```

`C_E=-287728.9703011956 J/mol` 已由 298.15 K NIST 气相生成焓锚定；液水和水汽保持同一个偏移。新的 Δu 是 EOS/理想模型转换，不是第二个生成能偏移，不得偷偷从账本扣除或作为热源。293–500 K 内必须导出最大 Δu、ΔCv 以及这一派生模型的源 DAG、R/M 与方法版本。不能继续标记为 `iapws95_real_fluid_helmholtz`。

该方案保留气体 `h-u=R_mix T`、`du/dT=Cv`，允许现有理想气面焓交换使用一致常数。液水内部仍采用原 IAPWS 质量 EOS 和 `h-u=p_liq v_liq`；不改其系数，摩尔量一律使用登记的 M95。别的物种的计量和分子量还必须通过元素/质量审核，不能由名称推断一致。

新 bridge 起步只能是公开方程派生、限定理想气近似的物性部件。热力学常数一致并不证明含载气混合物在全部压力/组成下接近理想；需单独证据/误差域批准。尤其不能将 500 K 饱和纯水汽（现有证据 Z 约 0.867）当作已验证理想混合气。

## 4. 液汽相平衡不能只写 p_water=p_sat95

纯水适配器的 `saturation_pair(T)` 描述原 IAPWS 两相平衡。含载气模型使用水汽分压；非理想混合物需要水汽逸度。液体化学势依赖液压力、水活度和界面/吸附条件。未知材料水活度不是 1 的同义词。

建议第一步仅做固定相库存的储能与开放流动验证，随后新增有来源的 `PhaseEquilibrium` 或 `PhaseTransferKinetics` 接口。不能用平衡关系冒充传质速度。其输入包括本次闭合的 T、p_liq、气相组成/总压、界面和材料状态，输出化学势差/平衡条件，或有来源的速率与适用域。

若批准“纯水液体 + 理想载气/理想水汽”的派生混合模型，相平衡应由同一模型的化学势计算：

```text
mu_l(T,p_liq) = h_l(T,p_liq) - T s_l(T,p_liq)
mu_v(T,p_v) = h_v,bridge(T) - T s_v,standard(T)
                + R_mix T ln(p_v/p_standard)
mu_l = mu_v
```

这里 h/s 均为摩尔量，`p_standard=1 bar`。需要新增并核读理想水汽标准熵求法：由 IAPWS 理想 Helmholtz 部分在原 R95、标准压力对应的理想密度下求原生 `s95_ideal(T,p_standard)`；不能用某个实际非理想水汽状态熵替代。可先在水的两相之间使用同一个明确原生熵基准；若与 NIST 其他物种反应平衡相连，必须对全部水相施加同一标准熵平移，并记录 298.15 K 的原始锚、舍入与来源。只做当前能量平移不能声称反应化学势已统一。

对 bridge 定义的理想水汽，标准熵沿温度由 `d s_standard/dT=Cp/T` 保证，压力项采用 R_mix。这形成可检查的理想气自由能模型，但其预测的液汽平衡压力不再被假定严格等于原始 `p_sat95`：原汽相非理想性和 R 约定都改变了模型。应报告差异并建立批准域，不能强行使用 p_sat95 同时声称新模型热力学完全一致。

在纯水原 EOS 模式下使用原相平衡，在 bridge 模式下使用派生化学势；两种模式的结果和模型 ID 必须分开。材料毛细压力/活度/非平衡传质未知时仍阻断砖的相变预测。极限 `p_v=0` 以明确的化学势负无穷极限/耗尽状态处理，不计算 log(0) 后伪装数值失败。

## 5. 从 500 K 向烧结温区延伸

已核读事实：当前 water adapter 公开域 293–500 K；已有 NIST 水汽 Shomate 首段从 500 K 开始。原始两者在 500 K 焓差约 −0.174811 J/mol，Cp 也不完全一致。不能仅凭原 IAPWS 发布温区更广就扩大已验证适配器域，也不能悄悄直接切换原曲线。[NIST 水气液事实出处](https://webbook.nist.gov/cgi/cbook.cgi?Name=water&cTC=on&cTG=on)见缓存 `source_facts.json`；本次该站点在线读取失败，使用已保存、hash 核验的必要事实摘录，未声称完成新的网页核读。

推荐独立 `PiecewiseIntegratedCaloricModel`：保留低温 IAPWS 理想 Cp 和各高温 NIST Cp 的原始温区，逐段积分 Cp 和 Cp/T，从同一 298.15 K 焓/熵锚构造连续 h/s。对每段保存由此产生的相对原 Shomate h/s 偏移，源系数不变，新模型具有派生方法 ID。Cp 在接缝可有有限跳跃，导数仅分段定义，温度求根/积分器须显式处理接缝，不假定全域光滑。

这不会“修复原 NIST 数据”，也不保证更真实；它是为了守恒和可逆热量定义而明确选取的派生模型，需独立审查偏移、温区与不确定度。每种活跃气体已有的其他 Shomate 接缝同样处理，否则仅修水汽无法保证全周期能量反演。未取得重叠数据或断层跨度不能靠任意插值填满。

液态水仍限已批准温压域：当液体实际库存为零时可继续高温气固模型；若液体尚存而超域则域退出，不能为了继续烧结强制删水或把液体转成汽体。高温固相矿物/液相烧结热力学是另一组必要材料证据，与此气相接缝设计不同。

## 6. 可直接实施的顺序与验收

1. **Storage primitives**：实现上述数据协议、源/参考态/摩尔基准一致性门禁，支持显式给定压力的多相能量评估与温度反演。用 manufactured 常热容固相只检验软件；它永不计入真实原泥覆盖。加入真实纯水和公开气体性质的非反应储能测试。
2. **Ideal vapor bridge**：将导出的 IAPWS 理想量转成 R_mix 模型；验证原 h 保持、Δu 和 Cv 差完全可重算。原水 adapter 不变，常数门禁不放宽。
3. **Mechanical/volume closure**：固定刚性纯水—载气容器作为明确分析系统，p_liq=P_gas，解体积与压力；未知砖毛细本构使用拒绝路径。然后接现有单面气流和液流接口，液流必须显式提供源或只在 manufactured 模式使用。
4. **Equilibrium/kinetic model**：先实现有共同熵/自由能定义的纯水理想混合物派生平衡，量化其相对原 IAPWS 的偏差；真实湿坯仍须实际水活度、界面与传质资料。平衡极限与有限速率模式分开，固体活跃反应继续使用有证据的计量/动力学。
5. **High-temperature continuity**：按来源 Cp 分段积分，保持锚定和可查偏移，加入接缝检验；之后才能申请跨全烧制温区的支持声明。

各步必须有实际执行记录，不能把本设计的验收清单写成已通过：

- 任意同相 N 加倍时 U/体积加倍；零库存不要求该相物性；参考体积与 mol/J 往返不改变库存。
- 固定组成封闭刚性系统：给定 T 构造 U，再反演；多初始温度、液/汽比例、压力，既检查温差也检查独立能量残差。
- 液体密度—气孔体积—压力闭合残差，正气孔约束；以独立求根/高精度分析基准核对，不能用求解器自己算出的残差代替独立审计。
- 常压纯水加热验证 `dH/dT=Cp`；固定密度验证 `dU/dT=Cv`；闭合路径 dU/dT 以有限差分核对，专门检测误用 sum Cv。
- 水汽 bridge 在 293、298.15、373.15、500 K 检查 h、u、Cp、Cv、R 和 Δu；源哈希或参考版本不同明确拒绝。
- 同一相变增量 `Delta N_l=-Delta N_v` 的水质量/元素完全守恒；固定总 U 反解温度出现相应降温，禁止第二次潜热源。极限库存不能被裁剪。
- 共用化学势下的平衡残差，水汽从 0 趋近、全液耗尽、无液凝结阈值分别测试；与原纯水 EOS 的差异保留而非被校准消失。
- 内部物质/焓流两侧严格相反，开放边界携入载气/水汽/液体焓均入账；计量参考态常数变化按元素守恒应不改变温度轨迹，非元素一致的任意相独立偏移必须检测。
- 500 K 及其余气体接缝：h/s 连续、u=h−RT、左右 Cp 正值，跨缝升温再降温不产生能量；原始曲线和派生曲线差异可复算。
- 所有验证区分公开方程复现、manufactured 数值检验、理想混合物近似和真实湿坯实验，不以其中之一替代另一项。

## 7. 不可绕过的剩余材料门禁

固体/伪组分生成能与热容、矿相和摩尔基准；原泥水活度/吸附；毛细关系与液体迁移；相间面积和传质速率；孔隙/闭孔/几何本构；固相反应与高温矿物液相；弹性/界面能和机械功，均须在各自适用材料域有来源。纯水物性和上述派生接口不会自动补足这些资料。接口/数值闭合可以现在实现；完整材料资格仍依据 Goal 合同验收。
