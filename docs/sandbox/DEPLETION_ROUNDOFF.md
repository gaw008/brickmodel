# 液耗尽事件的数值修正与存储舍入账本

已实现`depletion_roundoff.py`，仅是终端事件的数值写回部件；没有实现事件定位、界面模式切换或完整湿干积分。不允许调用者把任意小液库存直接当成已耗尽，后续事件主机必须先验证事件时刻/方向/程序节点及共同后续时刻误差。

输入为未修正的完整ConservedState、cell/液汽列、panel液初库存和已保存通量/源项、另行累计的正向蒸发积分，以及显式数值政策和累计器。Fraction重建panel液末量，要求输入状态恰是一次舍入后的该值；其已有panel舍入单列记录，由常规panel账本负责，不混入本次事件舍入。未出现负库存裁剪，也没有修改K或创建成核模型。

剩余液δ只能在局部液列4倍ULP和、绝对mol政策、至多1e-8倍正向蒸发积分三者内作数值相间修正。大气水库存ULP不能提高δ限。事件记录保存精确−δ/+δ、实际汽增量和二者差；实际汽相加在Fraction域进行再一次binary64舍入。局部half-neighbor-spacing按舍入方向选择真实相邻浮点间距，覆盖二次幂边界与最小subnormal。U和惰性列不变。

`DepletionRoundoffTotals`以Fraction累计事件存储舍入的符号和、绝对和及总数值修正量。每次与累计前缀分别受水mol、H/O元素mol和质量kg预算；元素限检查H的2倍量因此同时约束O。水摩尔质量为调用者显式声明并须由实际host水provider绑定，本模块不核验材料来源。逐事件/累计绝对误差不因正负抵消而消失。版本化to_record/from_record以有理数字符串保留精确累计值和原政策，恢复后不能改预算或清掉累计误差来通过。

这一累计器仅覆盖本模块的事件存储舍入。它不能替代原积分的全部face/reaction/panel误差、事件时间与全程物理守恒审计；不能把成对理想账本叫作实际库存逐位精确守恒。函数不验证传入的正向蒸发积分由真实速率产生，实际事件积分器必须从相间诊断单独积累，不能以净液流出代替。

事前政策和反例见research/DEPLETION_WRITBACK_PLAN.md。开发先因模块不存在RED；12项通过后添加二次幂/最小subnormal、反向符号但绝对预算累积及JSON恢复，恢复接口先RED后实现。最终15项通过0.06s，XML为research/depletion-roundoff-author-tests.xml。δ=ulp(.01)/2、汽=.1的反例实际汽增量0，但真实水存储差−δ被准确记录，在事前预算内可接受；第三次同号误差累计超限被拒绝。没有为了精确浮点配对把正常事件永远判为unsupported。

本部件为后续终端事件积分提供已测试的预算机制，完整湿→干→升温尚未完成。独立代码/数值审核另记，不把本说明当作审核已通过。
