# 接近的耗尽事件：数值有序路径

`DepletionPolicy.ordered_event_policy='ordered_affine_packet_v1'` 是显式数值选择，要求 `affine_midpoint` 和独立 approach 策略。默认 None 保留旧路径。没有修改原时间、库存、能量、温度、压力、伸长或修正预算。

初始 N/(-Ndot) 只是候选时间。新路径允许原普通正 stage RK 推进，在末端用共同的起点及中点观察构造每个湿单元的仿射库存多项式。只有最早数值根的上界严格小于其他候选根的下界，才按该顺序切换一个单元。精确重根或无法分离的数值根仍返回 unsupported。根区间属于数值近似，不是实际非线性物理轨迹的严格根证书。

每次切换后调用实际 mixed-mode 算子重新计算后续事件。一个待验收事件序列保存每个事件的状态、观察和排序证据，推进到同一个比较终点。两次连续细化及独立较细 approach 均检查完整事件序列、模式、逐事件与共同终点的 N/E/T/P/伸长。公开事件元数据中的误差为整个序列的保守最大值；逐事件原始比较留在 refinement diagnostics 中。

面板与修正按不同末端面板关联，整段通过原初前缀审计后才一次提交。中间取消、源身份变化、数值失败不提交前半段事件。阶段预测触发重排时只保留已接受的局部前缀；无法从当前状态定位到共同终点内的事件时明确退出，不重复无推进尝试。

核心返回独立 `OrderedPacketResult`，包含 `packets` 和 `packet_schema`。旧 `event_record`、案例服务及续算尚未支持这个结果合同，均明确拒绝；不得把研究结果去掉字段后冒充旧 v1/v2 记录。完整 packet 编解码、独立审计、续算、CLI/UI 接入仍是必需待办。

测试、审查、实际运行及其限度统一记录在 [ordered-packet-v1](research/ordered-packet-v1/README.md)。这项开发不提供原污泥材料参数或整砖现实验证，原空间收敛失败也不会因事件路径实现而自动消失。
