## Initial decision retained: REQUEST CHANGES (two bounded clarifications)

1. The quantity `D=eta*V0*sum(ell_dot_i^2)` is dissipated power, and the stated stress correctly satisfies `V0*Pvisc:Fdot=D`. Calling D the dissipation potential leaves a factor-of-two ambiguity for an implementation taking its derivative. Specify Rayleigh potential `Phi=D/2`, `Pvisc=(1/V0)*partial Phi/partial Fdot` at fixed F, or consistently call D power without a potential-derivative claim. The existing stress and energy-power formulas themselves need no change.
2. The wet isochoric, eta=0 oracle cannot assert constant temperature under arbitrary active phase transfer. Constant thermal U does not imply constant T when liquid/vapor inventories change. Require closed boundaries and fixed fluid composition (or explicitly zero phase rate/equilibrium) for the constant-T subcase. An active phase-transfer subcase should instead check conserved thermal U with a composition-dependent caloric inverse; it must permit latent cooling/heating.

Both were sent to root and author before completing this report. These are implementation/test-contract corrections, not a finding that the total-work derivation is inconsistent.

## Independent algebra checks

For the prescribed fixed-frame diagonal potential, differentiation gives `P_el,ii=(K*theta+2*G*dev_i)/lambda_i`, since the deviatoric components sum to zero. The oriented interface law can be extended on diagonal F as `gamma*A0*lambda_2*lambda_3`: each tangential derivative is `gamma*A0*lambda_t/V0` when the two tangential stretches coincide. An implementer must not assign the derivative of the restricted scalar `lambda_t^2` to both components and double the interface power.

At fixed solid inventory and constant intrinsic solid volume, `Vp=V0*J-Vs` gives `partial Vp/partial F=V0*J*F^-T`. Therefore `Ptot=P_el+P_interface+Pvisc-p*J*F^-T` and its contraction with `V0*Fdot` is precisely `E_el_dot+E_interface_dot+D-p*Vp_dot`. Subtracting the temperature-independent recoverable energies from the total-energy balance yields `Uthermal_dot=face_net+D-p*Vp_dot+body_heat`. No second viscous, pore-work or latent-heat term is justified. The initial abbreviated thermal equation omitted body heat; root corrected the final general equation to retain it.

This remains consistent when fluid inventories change: pore capacity depends on prescribed geometry and fixed Ns, while liquid/gas occupancy and common pressure are re-solved. Transport enthalpy already accounts for stream flow work. Fixed solid inventory is consequential: solid reaction, evolving intrinsic volume, capillary occupancy energy or a reference stretch that evolves with history would invalidate the present simple derivatives unless explicitly added.

For the independent isochoric path, `ell=(a,-a/2,-a/2)` gives `theta=0`, `sum(dev^2)=3*a^2/2`, and `sum(ell_dot^2)=3*a_dot^2/2`. Thus the proposed elastic/interface energies, dissipated power and constant-composition temperature formula are algebraically correct. The stated polynomial integral for the smooth log-strain path differentiates to `a_dot^2`. It is a distinct analytic motion adapter, not the existing stretch-interpolation law. Zero volume work with nonzero recoverable work is an effective discriminating test.

## Actual code compatibility and required implementation gates

Read current `solid_fluid_storage.py`, `solid_fluid_heat.py`, `integration.py` and the geometry/phase contracts. The design correctly identifies real, unresolved implementation work rather than claiming drop-in support:

- Existing `SolidFluidState.energy_scope` excludes elastic/interface energy; existing `ConservedState` has no per-instance energy-scope tag. A host identity alone cannot detect an arbitrary old state with the same array shape. The planned typed/identity-bearing initializer and runtime binding must enforce the declared total-energy scope, including restart/export use, instead of silently reinterpreting old thermal joules.
- Current `SolidFluidStorage.temperature_from_energy` accepts a scalar target and only assigns it an ulp-based representation allowance. A rounded total-minus-mechanical target with unpropagated uncertainty is insufficient. Either extend that explicit contract or perform the proposed total-energy forward inversion. Both residual signs and reported temperature radius must include mechanical/target bounds with directed arithmetic. Temperature-independent mechanical energy preserves the original positive thermal Cmin; it does not remove uncertainty from the inverse.
- `SolidFluidHeat` currently calls its thermal storage inverse before shared-face assembly. Reusing decoded states requires an actual factoring or explicit new evaluator. Passing total energy through the old decoder would be wrong. Current-volume constructor checks and all half-cell geometries must stay active.
- `integration.rk2` presently integrates only face species, face energy, reaction species and total cell power using its actual two stage weights. There is no accepted component-work hook. The proposed component record must be attached to the same evaluated stages, committed only for accepted steps and propagated through event/restart paths. Endpoint elastic-energy subtraction is a separate error check, not a substitute for the work quadrature.
- Reference geometry, fixed Ns identity, current positive pore volume, caloric references, manufactured gates and physical/numerical failure classifications remain required. The current state arrays alone cannot authenticate a new constitutive law or an arbitrary inventory layout.

These are mandatory next-slice tasks, not reasons to omit wet coupling. Initial exclusion of solid reactions is physically explicit and bounded; liquid/gas transport and existing water phase transfer remain required. Prescribed local actuators must supply the full stress; this is not a free, force-balanced sintering solution.

[Author-hosted primary paper](https://www.math.purdue.edu/~shen7/pub/sintering.pdf).
