# 非静止来源续算的运行前合同

基线92e5b85。本阶段保留完整Goal，验证非零导热的来源普通段、暂停/继续及纯数值检查点的
持久化读回。后者不是源会话的跨进程恢复授权，完整材料和全烧成周期资格保持false。

新案例`data/sandbox/cases/source-nonstationary-heos-v1.json`仅将旧案例的内部两面导热系数
设为(.5,.7)W/(m K)，初温设为325/327/329K。这些值沿用
`tests/sandbox/test_source_wet_column.py:setup`的制造测试设置；不是污泥实测。
原17来源资产、0.2kg干质量、固定可用体积/误差、相变/液流条件、全部误差界及验收政策不变。
现有SourceRunConfig和实际SourceWetColumn能直接表达这些差异，无需改变物性或绕过准入。

原湿干事件仍使用probe导出的微秒步长。数值接受candidate1后，为一个**新的普通段**
显式选择initial/max步长1/64s，声明终点为该实际末时加3/64s；最小步长、全部容差、
4步/4拒步/180s保持。选择原因是事件定位与后续导热的时间尺度不同：0.2kg的名义来源
干相热容在当前域内已超过300J/K，而这两面导热导纳仅约0.02W/K量级，1/64s远短于
名义导热时间尺度。此估计只用于数值步长初选，不能取代实际误差控制、物性适用性或收敛验证。
原参考政策与新普通段政策同时保存；暂停后不允许更改政策或重新开始预算。

在最终非editable安装后只启动一个有监督的原生比较任务，采用真实HEOS/NIST/Arlabosse
对象，不使用人工液体或monkeypatch。共享一个新父研究，分别真正重建并执行连续段与
暂停1步后继续段。整次任务另有共同97次RHS、16次额外湿查询及510秒守卫；各会话仍
保留自己的完整父成本。预期实际32+22+22=76次RHS、4+4+4=12次provider构造、初U仍3次，
但实际数字以保存记录为准，不能把共享父研究重算成两次或隐藏两分支总成本。
使用570秒进程监督限额及1秒清理宽限。已终态的旧原生任务不重跑。

验收必须包括：

- 父研究按全部原门槛数值接受，真实重建的来源/能量/算子/模式与保存末态一致。
- 新段至少一内部导热率和积分非零，实际U变化；至少一个逆温变化大于其两端保存的
  条件数值误差界之和。最终接受态必须与对应实际求值输入一致，不能借用预测阶段温度。
- 两路径除实际wall用时外，全部接受状态/精确时钟/步账本/拒步/回调结果逐项相同，
  暂停前缀完整复用；原湿初态起的全部累计账本在原逐格及全域N/U门槛内。
- 封闭边界无净外加热量，逐格交换和全域守恒分别核对；不以假定温度单调替代检查。
- 暂停普通检查点可以encode/decode并通过被动控制器核验；原会话仍使用它自身已签发的
  live检查点继续，不将反序列化数据私自塞入受保护源会话。
- 完整请求/返回、实际耗时与失败落盘。失败后先定位原因、保留数据，不能改门槛或
  延长资源限额取得通过。公开包不包含出版商原始资产，不能当作独立恢复包。

人工液体源码测试仅沿用此前已推导的1e-7Pa压力求根精度；真实HEOS案例仍为原1e-5Pa。
科学门槛、体积误差、温度反解等均未因制造测试而放宽。
