# 普通积分器的绝对时钟修正

分类：`numerical_policy`，ID `NUM-TIME-CLOCK-EXACT-BINARY-1`。这项工作修复重复绝对浮点加法产生极短尾步的成本与失败，不提供新的材料参数。基线提交 aab23b4。

## 原问题与最终实现

原活动相变制造案例 .5→.51 s、名义八步在 .5099999999999998 s 留下两 ULP 尾步，触发原时间预算。最终实现用 Fraction 累计名义二进制步长，接受后推进；两条拒绝路径重锚到真实接受时刻。端点仍转换为 binary64，实际 RK 和每项账本使用实际端点差，断点完整求值。最大步长约束名义步长，绝对端点独立舍入可能使表示后的间隔略大；不可将该数值策略当作新的物理假设。

第一次修复 v1 的真实完整安装测试为 1121 通过、2 失败。两项耗尽续算回归揭示：不同输入各自舍入，精确累加仍可能留下一个 ULP。因此最终 v2 保留原有严格局部合并界 min(ulp(target),32*ulp(min(h,target-at)))，并完整积分剩余区间。没有直接跳改状态/时间、放宽精度或增加资源预算。旧失败和测试真值推导修正全部保留。
