# 精确内核的实际取消与续算

`integrate_exact_depletion(..., continuation=ExactContinuationRequest(...))` 现可从同版本权威父记录继续。入场重新执行原始前缀、终端证明、全部事件比较和资源四项审计，再恢复完整数值历史及实际模式算子。必须使用原initial/start/end/fullpolicies；不接受单个partial报告作为许可，也不使用旧版本只读兼容规则执行续算。

原接受前缀、未提交试算历史、修正量、账本同对象关联、分项schema、累计计数和活动时间全部保留。新活动时间包含审计/恢复耗时，向上表示累计浮点秒，空闲时间不计入。资源用尽的父记录保持原resource_limit理由，零物理回调。`on_commit`仅在全局原子提交后发出不可变的(步数,事件包数,精确时间)，可用来确定性地请求取消；观察器异常保留已提交前缀。

## 适用边界

此阶段完成精确核心的同版本取消/续算，未接入旧CLI/UI服务的精确记录生命周期。父SHA及其来源由可信调用方/运行存储提供，核心请求本身不是外部文件真实性证明；服务还须保存父子关系与并发claim。重启自适应步进可能改变其他案例的网格，此案例的数值相同不能推广为普遍逐字重放。

当前仍是真实水物性配制造固体/反应/输运的限定案例。原污泥成套材料、三个机制组公开留出对照、全湿烧成冷却、空间收敛与多代/最终应用验收均保持未完成。
