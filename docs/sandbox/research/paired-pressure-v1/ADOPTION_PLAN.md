# Paired pressure adoption: conditional, explicit, and separately audited

Status: read-only design, 2026-09-08. No repository edit, EOS execution, or installation. This follows the actual paired_pressure.py / paired_pressure_host.py and current depletion comparison, not a proposal to replace all uncertainty semantics.

## Conclusion first

**The missing inverse-temperature tube does not invalidate this certificate against the pressure gate actually implemented today.** That gate is already conditional on the reported nominal temperatures. `depletion_integration.observe` obtains pressure errors from `base.storage_states`, while inverse temperature errors come separately from `base.storage_inverses`. `RigidStorage` computes pressure residual/compliance at its supplied nominal temperature (`rigid_storage.py`, lines 218–227); `SolidFluidStorage` adds volume uncertainty at the same temperature (lines 142–157). Neither pressure error includes an inverse-temperature tube. `depletion_integration.py` lines 808–814 apply separate temperature and pressure gates.

**The new shared-constant family still cannot silently take over the existing generic error family.** Equal source IDs or identical declared absolute errors do not establish correlated errors. Keep the existing default computation, records, rejection behavior, and historical audit unchanged. A new explicit versioned opt-in may use the paired certificate for the same reported-T pressure comparison, restricted to its declared manufactured constant parameter box. This is a conditional model-family comparison, not a retroactive proof that a run failing the old generic gate passed it.

If “pressure gate” is intended instead to bound pressure at every temperature allowed by the inverse energy error, **neither existing pressure comparison nor the paired module proves that stronger assertion**. Separate satisfaction of the T gate does not imply satisfaction of this stronger P gate. This is a disclosed existing limitation, not a newly invented reason to block the narrower numerical improvement.

## Concrete narrow interface

1. Add an optional typed `pressure_comparison` policy, default `None`. None executes the original formula exactly, including its cross-cell maximum aggregation; do not opportunistically improve/rearrange even that default formula. Proposed opt-in schema: `manufactured_shared_constant_reported_temperature_v1`; fixed qualification: `conditional_on_reported_temperatures_not_inverse_temperature_tubes`. It contains a complete tuple of cell-indexed `SharedConstantParameterBox` values bound to the original actual point identities. The case explicitly declares the hypothesis; constructing the box is an explicit action, never an inference from old envelope metadata.
2. Preserve both values in every opt-in comparison: `original_independent_pressure_difference_pa` computed verbatim by the old formula and `selected_pressure_difference_pa`. Also preserve `comparison_contract`, each cell's original point intervals, nominal T values and unchanged inverse T bounds, declared box identity, exact paired certificate record and input SHA, qualification, endpoint costs, and fallback reason. The policy pressure threshold remains unchanged. Do not overwrite original observations or their error bounds.
3. For every cell, obtain a bound on absolute pressure difference from `prepare_paired_pressure(...).certify()`. Combine cells by maximum, then combine event and common-time comparisons by maximum. Both consecutive terminal comparisons and the genuinely finer approach comparison use the same policy. A certificate already bounds the entire absolute root difference; do not add the nominal pressure difference a second time.
4. The current `DepletionEvaluation` deliberately drops actual inverses. Retain immutable, internal comparison snapshots from the already evaluated actual FreeSolidSlab output (full CurrentSolidInverse, state and actual operator binding) alongside reduced observations, only when opt-in is active. Do not serialize the provider graph. Do not invent inverses or perform a second total-E decode. Fresh observations, retained terminal observations, and any cache use require the existing source/content guards. A pure manufactured callback adapter without genuine CurrentSolidInverse stays on original behavior.
5. Adapter currently accepts one direct actual WaterPhaseTransfer and validates both states against its FreeSolidSlab. Both path operators must first be checked for compatible point/closure content. Preserve both actual operator identities and interfaces in the comparison record. Mode differences after depletion are permitted only when closure providers/point boxes genuinely agree; they must not be hidden by source-ID equality. Do not broaden exact host admission to a programmed wrapper until its actual bound inner host and time-dependent config have a reviewed contract.
6. Unsupported host or absent declared box yields `unavailable`, with original bound retained. With opt-in, a missing supported cell can conservatively use its independent cell bound; record this explicitly. The original global independent result remains available as a conservative fallback. Invalid source/state binding, endpoint failure, nonfinite input or provider mutation is a structured failure, not silently treated as an unsupported feature. Do not use a partially obtained certificate.

## Guarded cost and transaction contract

Each pair requires up to four liquid endpoint evaluations per wet cell, no endpoint work for exactly zero liquid on a side. One event/common comparison across C wet cells can require up to 8C calls. These are additional native calls even though no inverse is repeated. Count attempted calls before invoking the provider (including a failed call), record completed/failed counts and elapsed time separately from existing operator-evaluation counts, and include the time in the same cumulative integration wall budget. Preserve counts across continuation and discarded paths.

The existing adapter's `endpoint_observer` runs after a successful native call, so it is insufficient alone for pre-call cancellation, attempted-call counting or deadline checking. Add a narrowly scoped before/after call mechanism or guarded endpoint evaluator; keep the adapter's actual WaterState/source verification unchanged. Check cancel/deadline before and after each call and source binding before accepting the comparison. Any failure aborts only the uncommitted branch; no accepted event or corrected state is committed from a partially checked pair. Native interruption remains subject to the external supervisor; no new unbounded retry/refinement loop.

## Record, continuation, and service changes required together

`event_record.py` lines 301–319 currently reconstructs the old pressure formula from reduced observations and requires exact equality with the stored refinement differences. Therefore changing only `dp` is invalid: it creates an unauditable result. Add a version-discriminated audit branch with a strict whitelist, exact arithmetic replay of the pure certificate and its input binding, all cells/event/common coverage, and the original scalar diagnostic recomputation. Legacy records retain the old branch without new required fields.

Arithmetic replay proves the recorded interval calculation; it does not independently validate a fabricated native endpoint sample. Preserve endpoint/source evidence with immutable run manifest hashes and bind it to the actual states, original policy, box and runtime. Do not label JSON arithmetic audit as independent scientific validation of native liquid values. Record input/state/root binding must be checked, not merely the certificate hash.

Continuation must require the same comparison contract and complete cell boxes as the original policy; no switch from generic to correlated family midway, no reuse of old passes under the new family. Preserve cumulative costs and historical comparisons. Case parsing, catalog/source trace, run service and replay must identify this explicit contract and keep material_qualified=false. A new run may compare against the retained old failure; it cannot rewrite it.

## Stronger T-tube contract: exact missing piece

For a true inverse-temperature pressure guarantee, use outward T intervals [T_reported−epsilon_T,T_reported+epsilon_T] for each state and retain independent errors on both sides. Required additions are:

- Source-qualified enclosure of liquid molar volume over the entire T/P rectangle, including existing absolute volume error and stable-liquid/domain guarantees. Point samples or a local derivative alone cannot establish it. Temperature endpoint evaluation is sufficient only with a certified sign of thermal expansion over that whole rectangle; water cannot be assumed globally increasing in volume with temperature.
- Certified root containment for every T in those intervals (not the current nominal-T root intervals), and a strictly positive common compliance bound over that enlarged domain.
- Either interval liquid volume evaluation directly, or a domain-wide upper bound on |dv_liquid/dT|, plus existing pressure monotonicity and point errors. The actual DeclaredNumericalEnvelope exposes liquid |du/dP|, not this |dv/dT| bound. The energy derivative bound cannot substitute for it.
- Exact gas term T dependence is already available. Shared solid constants have zero T derivative only under the explicit new constant-box hypothesis. Arbitrary solid/reference error functions remain noncancelling without their own regularity contract.

An alternative proof uses |dP/dT| <= (Ng R/P + Nl L_vT)/C_min across the certified rectangle and adds each side's temperature-induced pressure bound. No cancellation of independent inverse T errors is justified. This may fail the original pressure threshold even when the separate T threshold passes; that is a legitimate stronger-contract failure. No widening of physical domains or declared errors is proposed.

## Minimum verification before actual event adoption

- Default-none exact regression and old saved-record audit parity; explicit opt-in/source mutation/unsupported admission tests.
- Analytic wet multi-cell comparisons cover both event and common times, unequal T errors, all-cell coverage, independent finer approach, and retained liquid error bounds.
- Tampered paired inputs/box/qualification/cost/coverage fail the record auditor; a manually created frozen record is not trusted.
- Cancellation and endpoint failure after an accepted prefix preserve that prefix and charge attempted work; continuation refuses policy/family changes and preserves cumulative counts.
- A bounded actual wet paired probe precedes a full event run; same physical initial state and unchanged six gates. Then a fresh opt-in event run reports both old and selected pressure diagnostics. Success means the explicitly declared conditional family passed; generic-family and full-Ttube claims remain unavailable.

Recommended next implementation is this explicit conditional policy + guarded comparison/auditor seam. It does not require inventing a T-tube claim, and must not be shipped as an invisible replacement for the original generic comparison.
