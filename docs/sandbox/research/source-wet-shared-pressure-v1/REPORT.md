# 来源湿格共享体积压力比较

基线 `fe9d684`。本阶段在原 N 格唯一单元湿→干转换中接入显式湿格联合压力比较。
完整 Goal 合同未改；原污泥完整材料域、反应/烧结/冷却、三机制公开留出、全周期和多代要求仍须完成。

## 实现与物理含义

`rational_intervals.py` 从旧 `paired_pressure.py` 提取四个纯有理区间运算。
旧的固体摩尔量、骨架体积和几何雅可比语义留在旧层；18 组完整结果和原错误保持相同。

`source_wet_shared_pressure.py` 声明同一实际 source storage 与体积对象，
针对同一体积下两个湿态端点建立条件性压力差界。两个空间格仍是不同体积参数。
共同压力区间 J 是原报告压力误差箱的向外 hull，受原机械/物性域约束。
每对端点最多查询四个实际液态 T/P 点；相同点仅在该对内去重。
请求前记录尝试，返回后先保存完整 WaterState，再校验返回值与来源关联。
取消、查询异常及返回值校验失败保留实际前缀和原异常链。

根存在符号与液体体积包络覆盖整个 J；压力差残差中共享体积才可消去。
完整证明仍依赖明确列出的平滑稳定液体、全 J 物性误差界和热力学导数界条件。
四个查询点检查一致性，不能证明这些全域条件或把声明误差变成实测误差。
详见 [物理合同](physics/CONTRACT.md)。

实际浮点闭合顺序是 `fl(fl(Nl*m)/rho)`、`fl(fl(fl(fsum(Ng)*R)*T)/P)`
以及最终 `fsum`。新计算保留液体、气体、求和三项全 J 舍入包络 Γ，
保留原实际流体误差和投影误差，再计入当前保存残差到根的距离。
扩大后的根箱重新传播完整逆温度区间，并取原、新温度斜率的较大值；
原体积对能量/温度误差的贡献未删减。选用 joint 界，不与旧独立界取有利的最小值。

`source_dry_transition.py` 在两条实际候选完成后，对事件/共同末端的未耗尽
湿格收集证据；pair 必须绑定这些候选的原格、原时刻和同一端点对象。
所选干格继续使用已有干态共享体积计算。原独立 P、N/U/T、时间和累计账本
全部保留；任一格压力证据未决或原门槛未通过，整次事件不能接受。
默认空策略继续原流程，显式取消/失败保留已执行候选和已返回的压力记录。

## 保存与资格边界

新 pair、支撑区间、逐项误差和原生水观测由研究 runner 的完整字段 JSON 保存。
研究序列化省略 live storage，但保留来源摘要和当次实际对象关联记录。
这些对象编号不能在另一个进程恢复共享资格。
现有 `source-observation-import/inspect` 仍只支持完整 source capture，
新 pair 不是该 CLI 的可恢复记录。本阶段不增加 live resume 或材料资格。

条件性数值事件通过、一次程序完成、公开材料验证是不同结论。
这里的原体积/输运/误差包仍含明确制造设定；真实水物性不使整个试件成为真实污泥砖。
