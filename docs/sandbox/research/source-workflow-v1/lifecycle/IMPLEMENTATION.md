# Service-managed RHS lifecycle

Only `source_run_service.py`, `source_trajectory.py` and the new `test_source_managed_lifecycle.py` are owned by this task. No provider, EOS, installed-package or native execution was performed. The parent owns the closed workflow worker, new profile/manifest and scope bootstrap.

`run_source_case(..., managed_execution: bool = False)` and `open_source_trajectory(..., managed_execution: bool = False)` validate the exact bool before I/O. True requires the real closed-workflow entry and explicitly selected `WORKFLOW_PROFILE`; no caller-created context is accepted as isolation proof. Default calls retain the old construction, solver and source-check behavior. The new private `_SourceWorkflowBudgetStop` distinguishes the closed worker's cumulative resource stop from a user's cancellation or an unrelated broken cancellation callback.

The run service admits after construction and closes in a shared `finally` helper before final encoding/publication. Individual exact RHS bodies still alone control `_rhs_scope`; initial energy, wet endpoint collection, observer and pause callbacks never gain a native RHS scope merely because a lease exists. The actual worker must implement the closed-process contract; this service does not establish it by hashing data.

An ordinary session reconstructs real providers without a lease. Each `advance` performs its original preflight, creates a fresh lease, charges admission time using a fresh post-admission elapsed calculation, then closes before returning or pausing. No lease token is stored on the session, checkpoint or serialized result. Previous parent counters and elapsed debit remain; online pause time is retained. Closing time is included in the outer elapsed total and checked against the original ordinary segment wall cap. The owned audit list is bound across calls to reject deleting prior lease evidence.

All lease paths retain an owned audit and a journal event, including admission/operation/close/audit/publication failures. A primary raised exception wins over cleanup or notification errors, whose type/reason remain in the audit and exception notes. An integrator return that is followed by a close or audit failure is retained as `session.last_execution` and in the failure journal, while the resumable checkpoint is cleared and the session closed. Run metadata and summary contain the same audit and explicit managed flag, and passive artifact verification checks that binding.

The test file uses explicit bootstrap/close/audit seams; it does not qualify fake objects as live source providers. Ordinary lifecycle tests run the real exact checkpoint integrator with the existing manufactured-rate fixture and verify 22 actual numerical operator calls across pause/resume, without new calls during passive replay. Tests cover all cleanup failure positions, primary/secondary exception priority, renewed lease identity, admission/online-pause/wall debit, retained late-failure prefix, default mode, prior-audit mutation and a real failure-record encoding/summary audit binding. Seven original default preconstruction/raw-journal tests also passed.

Evidence retains the original nine missing-keyword RED tests. `green01` has 18 pass and two implementation-coordination failures (an expected error-string mismatch and the parent's then-not-yet-added profile constant); these were addressed in the test seam without changing scientific thresholds. `green03` passed all 28 cases. `final01` was stopped during collection while the parent was adding the registry constant imported by its changed config module; it performed no tests. After that registry was available, `final02.xml/log` passed all 28 cases on the frozen files; `FREEZE.json` records actual XML attributes and file hashes. No failed evidence is overwritten.
