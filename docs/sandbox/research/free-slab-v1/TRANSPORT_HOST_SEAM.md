# Minimal dynamic multicell host seam (read-only audit)

Use SolidFluidHeat._assemble_decoded(amounts_mol, storage_inverses, temperature_brackets_k), not SolidFluidHeat.evaluate/decode and not DeformingSolidHeat.evaluate. The private assembler is already the reusable source-checked seam used by prescribed DeformingSolidHeat.evaluate at lines142–160. It accepts original SolidFluidInverse objects, checks exact inventory mapping, current bulk/pore/solid geometry and source IDs and temperature bracket, then performs gas/liquid/reaction/heat face assembly without a second thermal inverse. Do not relax those checks or pass DynamicSolidInverse in place of SolidFluidInverse.

## Required actual per-stage data flow

1. New exact-typed free slab host validates complete (cells, species) N, per-cell total E, positive n[cells]+one common t, frozen reference/provider/energy identity. Initially reject base.solid_reactions and enforce each cell's exact fixed solid inventory. Do not route through old _check_state, which intentionally rejects mechanical/tagged state.
2. From the SAME current geometry derived from full n vector and common t, each cell must produce current SolidFluidStorage, zero-rate skeleton recoverable energy, and total-E inverse yielding original thermal_inverse. Preserve original bulk/geometry/error and source identity checks. Choose each wet/dry bracket explicitly as DeformingSolidHeat.evaluate does, without calling base.temperature_brackets_for(tagged mechanical state).
3. Build transport=replace(base.transport, storages=tuple(s.fluid_template for s in current_storages), face_area_m2=current common face area, cell_widths_m=all actual widths). Build current=replace(base, storages=current_storages, transport=transport). This preserves exact fluid-template object bindings and reruns original 2-ULP bulk geometry gates. Do not leave reference widths or available pore volume in a current host. Geometry volume and selected cross-section must agree on float arithmetic under existing bound, not forced with loose tolerance.
4. Call current._assemble_decoded(actual N, tuple(inv.thermal_inverse), chosen brackets). It assembles N/V gas concentrations, mass-frame corrected diffusion, Darcy, Fourier, gas enthalpy and optional liquid transport using current dimensions. _liquid_faces uses current liquid saturation N*v/current_available_pore_volume, actual current areas/distances, and existing relations/connections. It may perform a liquid property query, but never another full total-E inverse. Thus 'no second inverse' must not be misreported as 'no extra EOS'.
5. Solve coupled free mechanics from ALL already decoded pressures using root's compatibility design; single-cell independently solved tangential rates cannot be concatenated into a common tangential state. Forward its rates as mechanical_rates_per_s. Preserve thermal face-species, face-energy and reaction arrays. Total cell power receives only correct allocated external traction, per-cell constraint exchange and body work, with full components. Do not copy prescribed DeformingSolidHeat's elastic/interface/D/pore power sum: those expressions belong to its prescribed work representation; a free host must avoid counting storage/dissipation twice.
6. New evaluation holds actual current_host, geometry, full inverses, thermal_evaluation and free solution; expose storage_states=thermal_evaluation.storage_states, storage_inverses=thermal_evaluation.storage_inverses, gas_states similarly. Preserve complete dynamic inverse separately. Source IDs combine real base/current providers and mechanics; no fabricated prescribed motion identity or reference geometry in current diagnostics.

## What needs refactoring / what does not

- SolidFluidHeat transport assembler needs no numerical rewrite or broad type guard relaxation for this stage. Existing private seam is adequate; modest named helper to rebuild current SolidFluidHeat from storages/current geometry could eliminate three-line duplication, but is optional. Keep old evaluate guards.
- DynamicSolidStorage currently guards cells==1 and calls solve_free_rates inside _complete (around192), so it CANNOT merely be instantiated once per cell. Factor temperature-independent recoverable storage/current-geometry preparation and total-E thermal inverse from free-rate closure into a reusable multicell point component. Its output must allow original SolidFluidInverse and current_storage before any mechanics solve. Or add a separate narrowly typed multicell point implementation reusing the same storage/error functions; do not remove single-cell guard without decoupling _complete. Current normal/common-tangent geometry must originate from shared full reference, not fabricated one-cell slabs.
- DeformingSolidHeat remains prescribed-only: exact point/motion checks and rejection of mechanical state should stay. A separate FreeSolidSlab host owns dynamic state and compatibility. Reusing its actual assembly pattern is correct; subclassing/spoofing its type or constructing PrescribedSlabMotion from current stretch is not.
- WaterPhaseTransfer must explicitly admit the new host and expose its genuine inventory/thermal templates/evaluation protocol as existing ClosedFreeSolidCell branch does. Do not bypass chemical/caloric reference/source checks, manufactured opt-in, or mechanical Rates forwarding. Programmed wrappers require separate deliberate typed admission and boundary work semantics; not needed for the smallest closed fixture.
- Reaction plumbing is present in assembler: later replace(base.solid_reactions,storages=current_storages) before replacing base; identity guard requires same objects. However a reacting free host needs composition-dependent recoverable energy, complete mechanical chemical derivatives and compatible closure first. Software reaction transport availability does not qualify fixed-N skeleton for changing solids. Fixed-solid first step is explicit incomplete mechanism, not deletion of Goal reaction/multicell/full-cycle requirements.
