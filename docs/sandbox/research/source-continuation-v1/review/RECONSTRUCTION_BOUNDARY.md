# Minimal source trajectory continuation boundary

Recommendation: add a real **ordinary mixed wet/dry continuation segment** after a numerically accepted source transition, and let that segment use the existing exact integrator plus its forthcoming committed-prefix checkpoint. Keep the old study as immutable evidence. Do not rebuild the entire archived trial/terminal/pressure graph into supposedly live objects.

This is read-only interface analysis at baseline `9d7beff`. No code or tests were changed and no EOS, decoder, model or numerical experiment was run. Exact file hashes are in `READ_ONLY_SCOPE.json`; the twelve rejection designs are in `REJECTION_CASES.json`. The other author independently owns the exact integrator checkpoint analysis; the recommendation below aligns with that author's committed-boundary design.

## What can actually execute next

1. Require the actual or independently validated saved transition to have `numerical_event_accepted is True`, complete candidate/reference histories, original gates and original full-path balances. An `executed_dry_candidate` alone is explicitly not event admission. The source transition's conditional numerical qualification can support declared-model execution while `material_qualified` remains false; material certification need not be invented to let software advance.
2. Make the branch choice explicit and immutable. A sensible first implementation selects candidate **1**, the shifted/refined path. Its history is **original initial → approach reference → shifted terminal prefix → writeback → candidate1 dry reference**. Candidate0 is a separate comparison path, not an interchangeable prefix. Preserve both for evidence and charge both for computational cost.
3. The new segment begins at `candidate.reference.times_s[-1]` with `candidate.reference.states[-1]`, not at the terminal root's lower bound or the uncorrected prefix. Preserve the exact Fraction clock and the original global initial state separately from this segment's initial state. Require a strictly later explicit exact target.
4. In the live process, use `candidate.terminal.dry_adapter`. For cold reconstruction, load the explicit frozen config/assets, run `build_source_run` to build actual supported providers/storage/column/adapter, and verify complete content identities. Use its **saved endpoint inventories and U**, not its zero-energy placeholders and not `_execute`'s initial-energy/probe/horizon pipeline. Call the new base adapter's `unpack(endpoint)` and `with_depleted_cells(endpoint, declared_indices)`, then require exact new mode/operator/energy/mass/species agreement with the recorded accepted endpoint. These constructor/state operations must retain their actual costs.
5. Evaluate a new ordinary segment through `integrate_exact` and the existing `_capture_source_observation` / observer journal path. All new RHS outputs must come from the new actual adapter. The first execution of this new segment needs its genuine initial domain evaluation; restoring a checkpoint within that same segment must not repeat the already committed initial probe. Fresh reconstruction anchors are still newly incurred work.
6. Validate each new committed prefix against the original full trajectory's N/U accounting before publishing a checkpoint. Persist a distinct continuation result and its original observation/cost history. A returned but unaccepted segment remains evidence, not the next resumable state.

## Why existing source trial classes are the wrong continuation container

| Existing interface | Exact boundary / reuse |
|---|---|
| `source_prefix_trial.py:287` / `:319` | A SourcePrefixTrial requires every inventory to be strictly positive. A legitimate mixed dry endpoint has exactly zero liquid in the depleted cell and is therefore `unsupported`. Keep this guard. A new ordinary segment must not call or impersonate this trial. |
| `source_terminal.py:99` / `:110` | Terminal construction requires an all-wet seed and creates a new affine event/writeback. Running it again at an already dry endpoint would replay the event and reset its accounting. |
| `source_dry_transition.py:27` / `:138` | SourceDryCandidate includes the event seed, terminal construction, dry comparison endpoints and event-specific qualification. It is not a generic post-event time interval. |
| `exact_source_column.py:83`, `:140`, `:148` | `unpack`, exact `breakpoints`, and explicit `with_depleted_cells` are usable on actual freshly constructed objects. These calls do not themselves grant event admission. |
| `source_prefix_trial.py:259` | Existing observation capture records the real attempt/return, validates source bindings and preserves failures. Reuse it with a new explicit continuation role and interval. Keep the durable observer for exceptions which prevent a normal return. |
| `exact_integration.py:143` | The ordinary exact-time integrator already evaluates mixed states through the adapter. The current result alone lacks the closure state needed for identical checkpoint restoration; the other author's accepted-prefix extension should supply that state, not a second integrator. |

## Content equality versus live identity

`source_study_schema.py:64` intentionally represents `SourceLiveReference` as archived identity/modes with `archived_reference_not_live_object_or_resume_authority`. `source_study_record.py:54` replaces actual adapter/storage fields with those snapshots. The `id(...)` integers in shared-volume/water-observation records are historical process-local data. They must never be rewritten to make an old record look like a newly executed one.

The useful content chain is `SourceWetStorage.binding()` (`source_wet_storage.py:134`) → `SourceWetColumn.binding()` (`source_wet_column.py:100`) → `ExactSourceColumn.operator_identity` / `energy_model_identity` (`exact_source_column.py:55`). It includes source/provider implementation, storage/energy reference, mass, volume/error, temperature domain, chemistry-disabled configuration, transport, layout and modes. A new actual object may match that complete content without sharing the old process id. Validate the new objects' own guards, compare their content to the accepted evidence, and retain a **new reconstruction binding**; do not assign old `_identity` or private binding bytes into a different object.

Narrow numerical records such as state, policies, exact time, ledgers and `ExactIntegrationResult` can use the existing **restricted** `source_study_schema.reify` (`:245`) after full record audit. That function deliberately rejects live-dependent trial/approach/refinement/terminal/candidate/transition/shared-pair types. Keep those exclusions. Passing `SourceStudyNode` to a runtime constructor or inventing an `ArchivedTrialView.check()` would bypass the intended boundary.

`SourcePrefixTrial.check` (`source_prefix_trial.py:121`) compares actual adapter content, original policy/control bindings, source captures and saved reference replay. A deliberately constructed, newly typed trial using a matching actual adapter could in principle revalidate those numerical fields, but it still proves only the original strictly positive trial and not a whole continuation ticket. It is not needed for this minimal runtime path.

`SourceDryCandidate.check` (`source_dry_transition.py:52`) also needs its live terminal and each endpoint's `bound.storage is corresponding actual storage`. The selected endpoint view has its own identity guard. `SourceTerminal.check` recomputes the original event construction. Reconstituting this entire graph is unnecessary to advance the saved endpoint, and using old ids does not satisfy these contracts.

Individual `SourceInversePressure` / `SourceDryPressure` enclosures can be freshly constructed against new matching storage and the saved typed state/inverse through their existing pure functions; their strict source/model/error decomposition is rechecked. This does **not** authorize copying old shared certificates. `SourceSharedDryVolume.check` and `SourceSharedWetVolume.check` deliberately compare actual storage/volume identity, while wet observations additionally bind their actual water object. Leave all old pairs as historical evidence. A future new comparison must declare correlation on the new actual common object and obtain the evidence required for its new endpoints; do not assume old pressure boxes or machine residuals cover a future state.

## Preserve the complete trajectory and real cost

`compare_source_dry_candidates` explicitly computes candidate1's balances with its preceding `refinement.approach.trial` (`source_dry_transition.py:503`). `_audit_balance_fields` (`:276`) already maintains represented and full-source exchanges, each cell's and global original absolute N/U gates, the single writeback correction and event roundoff storage term. The smallest extension is to let the same step/record loop consume validated post-dry reference segments, e.g. an empty-by-default `post_dry_references` input. Existing callers stay numerically unchanged. Do not manufacture a single solver-returned result by concatenating separate runs without labeling that composition.

For every new segment require exact predecessor time/state equality, unchanged original numerical/energy/mode contracts, and preserve the original global initial state. Do not merely add old and new residual summaries: reconstruct the conserved exchanges from all original ledgers and the writeback, then apply the original per-cell **and** global budgets. Do not reapply the depletion correction or grant another roundoff budget. Event-specific element/mass qualification keeps its original scope; this continuation does not silently promote it to raw-sludge chemistry closure.

The lifetime cost ledger is separate from the selected physical path. Preserve all prior source starts/returns, rejected/unselected trials, wet comparison requests, construction/initialization work and elapsed measured work. Add reconstruction anchors, failed new requests and new segment work; do not reset the original 97/16 total source/wet request allowances on each continuation. Per-segment/per-trial limits remain explicitly scoped and cannot masquerade as the lifetime cap. Persist the remaining resource budget and block before new work when exhausted. Offline waiting time is not a measured solver execution time; keep it distinct from cumulative active work and the new process's supervisory wall deadline.

The current `ExactIntegrationResult` does not store next adaptive h, knot position, accumulated exchange arrays or the component-schema initialization state. As the other author confirmed, identical restore requires a committed exact-integrator checkpoint, including its original segment initial state/clock, current state/clock, next h, exact accumulators, schema and resource counters. Mid-trial cancellation is retained as an attempt with diagnostics; it is not a silently rollbackable checkpoint that preserves identical future callback counts. Commit and resume boundaries must be explicit.

## Keep this implementation small and executable

Add one source continuation segment/capsule type around the exact integrator's checkpoint, not a parallel depletion controller. Its minimal binding consists of parent record/case/config/implementation digests; selected path index and accepted event decision; original global initial/clock and accepted endpoint; exact target; current modes and full operator/energy/policy bindings; cumulative balances and lifetime cost; returned reference/captures/checkpoint/status. Extend the existing passive codec/audit only for these concrete fields and retain the parent's original record unchanged. A new operational continuation entrypoint can validate that contract while the original passive record's `resume_authorized=False` remains true to its original meaning.

A version boundary is unavoidable: the current source replay checks the full `runtime_before` identity (`source_run_service.py:417`). Adding continuation code changes that identity. Do not pretend the old `9d7beff` native record is automatically compatible by ignoring the mismatch. The smallest useful acceptance can create an accepted transition under the **new frozen version**, continue an actual ordinary segment, pause at a committed prefix, reconstruct with the same version and finish. Supporting old-version migration is a separate explicitly reviewed compatibility contract; it is not needed to prove the new runtime advances. This avoids spending a stage solely on passive file validation.

Meaningful acceptance is actual new time advancement and fresh observations beyond the accepted event endpoint, plus an uninterrupted-versus-committed-pause/resume comparison under the same exact-integrator contract. Preserve all original time/state/ledger bytes up to the committed boundary and charge any reconstruction work separately. Cover large exact clock origins, original program knots when the reconstruction profile supports them, all original policy fields, per-cell/global residuals, cancellation after an occurred return and resource exhaustion before a new call. The current fixed N3 config builder cannot reconstruct a programmed source profile; reject that archived profile rather than silently replacing its boundary program.

This slice should stop with retained prefix when another wet cell exhausts, the declared dry mode would rewet, or an original domain/gate fails. Locating a second event or permitting nucleation requires the corresponding real model/controller extension. That limit does not prevent the ordinary supported mixed-state trajectory from advancing now.
