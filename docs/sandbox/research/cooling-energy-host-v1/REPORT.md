# 原生总能量冷却宿主验证

常系数参考半板现在可通过项目原生 `ConservedState / Rates / integrate / StepLedger` 演化总内能，再全局反解温度和共同应变。逐格热流与局部约束功共同进入实际接受账本。V2粗细两档均完成0–10秒，并通过全部事前登记的温度、解码、守恒与资源检查。

这些结果属于制造参数下的数值与接口验证，没有取得真实原污泥/砖材料、化学质量或全周期资格。完整Goal仍未完成。

## 原失败与必要修复

V1的native01真实退出1，监督0.710509334秒；粗档停于0.3秒，以 `numerical_failure / unresolvable_stage_time` 结束，细档未启动。保存61个状态、60步、421次RHS且无拒步。精确匹配旧参考的只有0、0.1、0.2秒三个点；下一个原时刻是相邻浮点数0.30000000000000004，不能把0.3冒充它。

独立前缀复算通过：最大逐格/全局残差3.742028e−14/4.441586e−14J，7条已保存完整反解证书通过。此结论仅表示保存前缀内部一致，原完整区间、时间比较和总通过标签仍失败。

修复在提交候选前检查其是否留下不可表示的RK尾段。必要时将剩余区间分为两个可计算的区间，再按实际端点重算所有阶段和热/功权重；既不向前扩大候选，也不移动已经接受的状态。真正相邻到无法积分的两个forcing knot仍明确失败。每档比整除名义步数多22个接受步是实际记录；驱动未逐项记录调度分支，故不把22直接当作已独立计数的修复触发次数。

首次clock回归误用非法功分量名而失败，修正夹具后两项回归真实复现 `unresolvable_stage_time`；两份RED均保存。修复后源码/非editable安装各183项受影响测试通过，分别2.13/1.36秒；独立代码审查另4项线性通量和预算回归通过。原材料、精度、最小步长、最大接受步与墙钟政策保持不变。

## 储能、来源与复现边界

储能推导和接口见[STORAGE_AND_HOST.md](STORAGE_AND_HOST.md)。储能Jacobian与温度率矩阵不同；把Helmholtz能当内能、遗漏逐格功或错用矩阵的纯代数反例已覆盖。全局反演使用可证含根区间与区间Newton收缩，失败时保持域无根与数值未解决的区别。原二分版本与证书舍入失败均保留，性能改进没有改变物理或解码政策。

最终158个Python模块/165个包文件与实际安装逐字一致。相对V1仅integration.py变化，其他164文件不变；相对基线3c61bf7新增storage/host并修复原生时钟。首次构建因网络限制失败，已授权隔离安装成功；V2从缓存离线构建成功，不增加依赖。

每格显式[2,3]mol库存只是原生接口的固定记账输入，不参与常C体积内能、反应或气体EOS。它不对应已验证的化学组成，不能推导真实密度。实际全部库存字节保持，物流/反应源为零，积分伸长始终None，共同面内应变只是代数输出。

原生求解器没有连续稠密输出。本研究只对实际RHS与接受状态执行域守卫；不能声明未知连续真解全期同域。全部接受E状态与StepLedger保存，但完整温度反解证书仅保存共同点和最坏见证；RHS只保存在线摘要和每512次试探见证，不能称全部RHS原字段已独立重放。外部强杀时未返回/未落盘的内部接受前缀仍unknown。
