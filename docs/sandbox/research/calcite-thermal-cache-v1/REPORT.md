# 方解石热化学重复求值的有界性能核查

从已完成的128格基础轨迹取0、2000、6000、8000、14000、18000s六个完整观察。原输入与这些观察均保存于`selected-observations.json`，选择时没有改变值或重建模拟。依次核对每格来源、全部内部面，再从原积分变量重做温度反演、平衡分相和表面求解。

精确温度缓存的容量0、256、1024分别使用新建模型。未取整温度、插值或更改公式；只在本诊断实例中包装原有物性方法，生产模型和正在运行的审计尚未修改。256和1024相对于容量0的**全部来源残差、内部面、重建物理库存、每格状态、储库、表面及导数记录逐字段完全相同**。

受测工作总计768格，容量0的剖析记录50706次单相物性求值；256时降至16152次。相同机器负载下三次带剖析总耗时分别0.492288、0.355965、0.374995秒；1024容量虽然减少未命中，没有表现出更短实际时间。此处计时只是本机六个观察的记录，不外推为完整轨迹固定提速比例。

剖析同时显示，反应标准热化学仍有12660次聚合调用，同一温度下的重复聚合是下一项可核查改进。下一阶段先比较组合缓存全部字段，再在已存在的小网格完整轨迹上核对原物理预算。没有中断128格长审计，也没有将性能测量当作其完成证明。

本阶段保存脚本、根参数、六个完整观察、三份剖析及原始结果。未新增或运行软件测试，未生成或比对SHA。`material_qualified=false`、`training_eligible=false`。

## 组合缓存与完整轨迹审计

组合方案复制独立审计实例的相对象和反应对象，再对单相与反应标准态方法的精确浮点温度参数做有界记忆。当前消费者只读取返回的字典；无温度取整、插值或平衡分相/表面根缓存。入口在 `examples/sandbox/calcite_exact_thermal_cache.py`，完整审计仅在根参数显式提供 `exact_thermal_cache` 时启用；原参数路径保持不启用。

复用同一六个原始观察，容量0、256、1024的全部物理字段完全相同。反应标准态实际计算由12916次降为3521次；256容量的单相计算合计16151次。三档含剖析耗时分别0.502406、0.326302、0.337758秒，仅说明这次有限工作量，不外推完整大网格提速。全部结果、缓存计数及剖析位于 `data/sandbox/research/calcite-thermal-cache-v1/combined/`。
