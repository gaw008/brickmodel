# 来源库存首根引导的单次正库存试算

基线 ee0ed24。新增 `source_approach`，复用原库存首根排序、原时间步约束与
`SourcePrefixTrial`，从实际保存的起点/中点提出更短区间，并重新求解。
它是一次有检查的数值推进接口，不提供真实耗尽时刻或干态转换。

## 实现

`propose_source_approach` 先验证原试算的完整来源与政策记录。原完整前缀即使
因负库存失败，只要起点与 Euler 中点的实际求值完整有效，仍可据此建立面板。
原失败状态保留；取消/资源停止的试算不能据此自动重启。

全部 4N 液/气库存参加首根竞争。唯一首根为液体下降穿越时，继续细化其原
包络直至严格正下界。根排序与取得正下界共用原细化预算；显式记录
`min(原 maximum_refinements,256)`，不修改原政策，也不重新给一份预算。
原排序与另存的收紧根分别保留。选择

`h = downward_binary64(min(safe_inventory_fraction * root_lower, maximum_step, horizon))`。

若 h 小于原最小步长则拒绝；所有库存多项式在 [0,h] 的精确最小值必须严格
为正。零初始、气体先耗尽、并列首根、切触、细化未决和炉程内部节点分别保留
受限状态。无根返回普通积分建议，由原 `integrate_exact` 负责，不新建控制器。

`evaluate_source_approach` 只执行一次新的原 `SourcePrefixTrial`，实际求值新
起点、中点和终点，并完成同一区间的原积分器参考。原 N/U 归一化比较门槛不变；
原事件政策的 N/U/T/报告温度处 P 门槛与条件逆温度压力门槛另存。数值试算通过
不意味着这些附加门槛全部通过，也不意味着事件时间准确。

完整嵌套事件政策在运行前复制，运行后核对全部结果绑定。后处理若失败，
`SourceApproachAssessmentError` 保留实际 trial、失败阶段、已完成的比较/压力
证据与原异常链，避免丢失已经耗时求得的结果。其字段是失败诊断，不能当作
已验证结果。此接口尚未接入通用记录编解码、CLI 或界面。

## 实际验证

| 范围 | 结果 |
|---|---|
| 首轮新增模块 | 20 项 / 4.24 s |
| 最终源码：新增模块、首根、试算、端点与逆压力 | 135 项 / 78.04 s |
| 同批非 editable 安装 | 135 项 / 76.62 s，XML 零失败/错误/跳过 |
| 安装身份 | 122 个 Python 模块、129 个包文件与源码逐字匹配 |
| 独立纯数值检查 | 109 项 / 0.03536 s |
| 独立代码行为检查 | 3 项 / 7.97 s |
| 独立 Python 反例 | 12 个案例分别有最终通过证据 |

独立精确案例覆盖完整 N3/12 库存竞争、初增后降、下降后回升、切触、同时首根、
最小步长边界及向下取整。预算反例实际需要排序 2 轮，原总预算 3 只剩 1 轮，
仍无正下界时必须拒绝。它们是制造多项式证据，不能替代实际水或原污泥验证。

制造水的实际来源主机案例保留了原失败前缀的 2 次求值，新试算通常包含 11 次求值。
独立恢复案例在第 6 次求值发生 DomainExit 后，由原参考积分器拒步恢复，最终
20 次求值、1 次拒绝成功；该测试明确给予 32 次预算，不声称 16 次也足够。
回调修改原积分政策时，结果检查拒绝成功但保留包含 11 次求值的已完成试算及比较证据。

保留的验证错误：Python 审核最初误以为 adapter 身份修改后还会进行第 2 次
调用，实际原 guard 在第 1 次返回后立即阻止继续；修正的是审核预期。
首次安装身份检查早于 XML 写入而遇到 FileNotFoundError，等待原进程正常结束
后复核，未重新安装或重跑测试。原始记录均归档。

## 真实物性运行

执行前条件与预算见 [PREREGISTRATION.md](PREREGISTRATION.md)，实际运行器为
[run_native.py](run_native.py)。安装后仅运行一次，完成于 32.312098 s，原
210 s 外层预算与每试算 180 s/16 次回调上限不变。4 次 HEOS provider 构造和
各自参考锚点、1 次初态 U 求值另记；14 次实际来源回调为初始速率探测 1 次、
原失败种子 2 次、新试算及参考 11 次。新试算实际 26.083941 s。

该 N1 低温封闭案例采用原公开干物 Cp、水和 O2/N2 物性；体积、几何、初态与
相变传递系数明确属于测试设定。无内部面、无材料化学转化，不代表原污泥全域。
测得初始相变速率 1.3567713867956468e-5 mol/s，以它计算的尝试区间约
0.1105565768 s 使完整前缀越过零库存。原实际中点仍合法；原首根排序与一次
正下界细化给出约 0.0138195721 s 的新区间。

新的实际中点、终点及同终点参考都已保存；参考 1 次接受、0 次拒绝。原 N/U 归一化差异为
3.0658550033357416e-10，满足原门槛 1；原事件 N/U/T 三项通过，报告温度处
压力门槛未通过，条件逆温度压力门槛也未通过。原完整压力认证仍 unresolved，
事件时间 not_evaluated，event_admitted 和 material_qualified 始终 false。
这个结果通过的是正库存数值试算；没有掩盖压力门槛未能认证这一结论。
报告温度处成对压力上界约 0.00222645 Pa，条件延拓上界约 0.00238482 Pa，
两者均高于原 0.0001 Pa 门槛；判定使用保存的精确分数。

完整原生 JSON SHA-256 为

## 适用边界与下一步

正性属于保存速率所定义的数值多项式；新试算与参考的相符仍属于限定数值证据。
尚缺独立来源 EOS/材料误差认证和真实事件时间；不进行归零修正、干界面切换或
再润湿，不修改旧机械专用耗尽器的类型门槛。输运耗尽所需的成对液体及同供体
焓转移仍须独立处理，不能使用蒸发修正额度支付排液残差。

下一项沿用 [既有路线](../source-prefix-trial-v1/next-route.md)：用独立实际求值的
粗细面板、相同首根标签和源/政策，比较根区间；不同起点/时间的状态需实际续算
到共同终点后，才能使用原 N/U/T/P 门槛。不能仅对同一对样本多做一次二分就称为
时间细化。仍保留事件未准入，直至必需条件成立。

完整原污泥材料包、反应—烧结—冷却、三个机制组的公开留出验证、全周期收敛、
来源应用/恢复及多代搜索仍是 Goal 必需范围，均未因这个增量而完成。
