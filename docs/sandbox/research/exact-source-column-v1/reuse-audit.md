Read-only source audit; no repo changes, EOS calls or tests. The three numerical tools below can be imported from their current modules. No relocation or duplicate root/minimum implementation is needed.

   - Definition at `mass_wet_exact_stage.py:132`, `minimum` at line 140.
   - Fields `family, cell, index` are labels, not restricted to A/B or two cells. The polynomial is `initial + linear*t + quadratic*t*t`.
   - `minimum(duration)` requires exact `Fraction` coefficients and exact positive Fraction duration. It evaluates both endpoints and the interior vertex only when quadratic > 0; returns `(minimum_value, earliest_argmin_time)` by tuple comparison. It catches interior dips even when endpoints are positive. It has no source, material, EOS, two-cell, kg/mol or root-order dependency in its arithmetic.
   - Source column can directly instantiate this class for every actual declared inventory, using `(rate_mid-rate_start)/H` as quadratic coefficient when midpoint offset is H/2. For arbitrary interior sample offset hm the coefficient is `(rate_mid-rate_start)/(2*hm)`.
   - Do NOT call existing `components`, `inventory_derivatives`, `build_panel`, `validate_positive_panel`: lines 265, 283, 297 and 311 respectively hardcode `WetRates`, 2 cells, 2 A/B solid inventories, and a 12-inventory schema. In particular line 287 liquid derivative is only `-phase_water`, which would drop the new liquid faces. Root's new source N-cell component adapter/panel is necessary; the mathematical minimum need not be copied.

2. `from sludge_sandbox.exact_affine_depletion import ExactAffineSamples, locate_exact_affine`
   - `ExactAffineSamples` lines 32–75 is already one-cell, host-independent numerical evidence. No `WetPair` requirement. Supply exact clocks plus actual represented float observations.
   - Its three signed liquid terms are explicitly **left liquid face, negative right liquid face, cell liquid source** (line 34). For source liquid column use `(J_liquid[i], -J_liquid[i+1], -phase_water[i])`, preserving the individual signed components. Open liquid boundary is the actual zero boundary rate. These are liquid mol/s, never total mass or gas flow.
   - The separate `evaporation_*` values must be signed **phase_water** rates (positive evaporation). `gross(h)` integrates the positive part of this affine phase rate exactly, including a zero crossing; it must not receive positive net liquid removal or sum of face losses. Liquid transport is consequently compatible without changing the algorithm.
   - Preconditions lines 45–59: exact ordered clocks `start < midpoint < upper` (midpoint need not be halfway); strictly positive initial liquid; complete finite three-term tuples; nonempty unique source labels; derivative strictly negative at both domain endpoints (`max(r,r+aH)<0`), and final inventory <= 0.    - `locate_exact_affine` line 129 returns `ExactAffineEvidence` via bounded dyadic refinement, maximum 256. Preserve these gates even if a candidate exhausts the refinement budget.
   - Drainage-only with zero positive phase evaporation gives no positive evaporation-based correction budget. This reuse therefore may fail to authorize residual correction even though a net-liquid root exists. That is a preserved limitation, not permission to relabel transport as evaporation.

## Boundary of this audit

`exact_depletion_writeback` (`exact_affine_depletion.py:170`) is not a drop-in source kg-solid state adapter: it requires mol-column `ConservedState`, correction policy/totals and explicit clock evidence. Its docstring correctly says it checks arithmetic, does not authorize an event or choose a dry constitutive branch. This audit deliberately makes no new writeback design; another agent owns that physical/state transition decision.

Recommended sequence is: root's complete source component/panel builder → existing `InventoryPolynomial.minimum` for every inventory → explicit fluid-mol numerical projection into existing `order_exact_affine_roots`/verifier (which constructs existing samples/evidence) when event localization is needed. Use direct `locate_exact_affine` only where a single candidate has already been justified without omitting competing wet cells. These utilities require no EOS evaluation; source physical bounds, actual coupled recomputation, source identity and acceptance audits remain outside them.

## Addendum: explicit ExactSourceColumn adapter and generic integration

The proposed adapter is feasible without widening the old mechanical driver:

- Fluid-only ordered `(Nl, O2, N2, H2O)` columns are all mol. Store actual per-cell total U, including fixed dry-solid source caloric energy, in `ConservedState.internal_energy_j`. The dry masses stay in SourceWetColumn.storages; include every fixed mass, caloric binding, fluid provider/source identity, volume contract, modes, liquid transport and program in the adapter energy/operator identity. Every encode/decode checks that identity and reconstructs each source state through the actual storage `.state`, never infers dry mass from a mol column. An exact tuple energy identity is supported by `integration.py:121–137`.
- Map each actual SourceColumnRates face once into Rates: liquid component J, the three gas components, and full face_energy including donor liquid enthalpy; source liquid=-phase and vapor=+phase, dry gases zero for this reaction-disabled branch. `cell_power_w=0` because existing total U already includes phase energy; no latent-power duplication. Keep mechanical stretches/rates both None. `Rates.derivatives` (`integration.py:180–197`) already handles arbitrary N and rejects mismatched state/rate mechanics, shapes, nonfinite derivatives and outflow from a zero inventory. It introduces no free-slab requirement.
- `integrate_exact` (`exact_integration.py:112`) accepts any callable returning Rates (type/shape validation lines 124–146 and 183–197). Mechanical controls are conditional on non-None stretches (125,152); they are not mandatory. Thus `ExactSourceColumn.__call__` can be used directly for ordinary exact-time source integration.
- Preserve exact boundary program times: feed ExactEventTime to the source operator and pass its actual strictly interior, sorted unique breakpoint times to `integrate_exact` (`134–147`). Never convert exact stage times to display floats. The autonomous source operator may ignore the exact time after validating it; the programmed source must use the original exact program view.
- **Numerical method distinction:** `integrate_exact` uses two-half SSPRK2/Heun with full-step error comparison (`214–239`, `282–294`), whereas existing `integrate_source_column` uses explicit midpoint. Equal point rates can be bit-identical, but trajectories are not expected to share the old midpoint golden. Validate the adapter's RHS/face-energy/component mapping exactly against the old source operator, and use numerical error/conservation checks for the new integration path. Do not weaken the old integrator's thresholds to create apparent parity.
- **Ordinary acceptance is not an event certificate:** generic exact integration checks finite/nonnegative stage inventories (`199–204`), numerical error and cumulative ledgers; it does not invoke InventoryPolynomial.minimum or root-order evidence automatically. Its multiple samples can share a timestamp but correspond to different full/half predictor states. Any affine event panel must bind explicit actual stage roles/state identities, not select a sample by time alone. Source event inventory minima/root ordering remain an explicit layer using the existing tools described above.
- **Diagnostics:** Rates carries aggregate face energy, not the complete donor-liquid enthalpy/decomposition fields from SourceColumnRates. Preserve those source observations alongside accepted/trial panels if later audits need their per-channel projections; do not claim generic ExactStepLedger alone provides the existing richer source-specific energy decomposition.

The old free adapter/driver must remain restricted:

- `ExactFreeWaterTransfer.__post_init__` (`exact_free_host.py:42–44`) requires exact WaterPhaseTransfer wrapping exact FreeSolidSlab; `.evaluate` at 65 calls `.evaluate_autonomous`. SourceWetColumn is neither, so it should get the new explicit adapter, not a subclass/type bypass.
- `integrate_exact_depletion` (`exact_depletion_integration.py:104–125`) explicitly requires ExactFreeWaterTransfer, WaterPhaseTransfer chemical reference, matching original energy binding, non-None mechanical stretches and stretch policy. Its proposal selection (`167–176`) directly accesses liquid_index, wet_cells, and `.cell_transfers` and rejects net depletion unless phase evaporation is positive.
- Later event comparisons are mechanical-specific: vectors from `.base_evaluation.storage_states/storage_inverses` (`244–248`), stretch differences (`278–286`), mandatory stretch audit accumulators (`303`) and per-interface stretch closure (`323`). These are substantive physics/state contracts, not a superficial type guard. Do not simply add ExactSourceColumn to that entrypoint's accepted types.
- Therefore direct `integrate_exact` plus explicit Source adapter is the smallest actual integration reuse now. `order_exact_affine_roots` can consume the same fluid state/Rates projection without a second adapter or duplicate roots. Final source event transitions/driver contracts remain separate work; this note does not authorize the old mechanical depletion packet for source rigid cells.
