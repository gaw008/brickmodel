Arlabosse source caching must preserve a content contract, not merely an equation value. Baseline 86d9733 was clean when this review started. No implementation is changed or approved by these design notes.

`arlabosse_caloric.py:72` currently reads the exact metadata file, verifies the fixed SOURCE_SHA256, parses it, resolves every named asset under repository_root, refuses path escape, and verifies every asset hash. Construction and each public cp/delta_h/registry_payload operation call it. Metadata can live at another path (the tests intentionally copy it); matching content is the contract, not a requirement that the metadata path equal one original pathname. Assets remain under the declared repository root. Missing files become CaloricError with the original OSError cause.

Important existing refusals and parameter guards:

- `test_arlabosse_caloric.py:test_binding_changes_refused`: modifying metadata after construction must invalidate the next cp and registry export.
- `test_missing_or_altered_assets_refused`: modifying an asset after construction must invalidate the next delta_h. Source deletion after creation is also tested through ArlabosseMassCaloric / FixedMassCaloricStorage.
- `test_source_mass_caloric.py:test_mutation_and_missing_source_are_not_silently_accepted`: changing the exact reference temperature invalidates its stored model identity; deletion cannot be hidden behind an already constructed provider.
- Runtime fake provider / caloric / chemistry substitutions are refused before invoking their callbacks. Cache lookups must not precede these actual-type checks.
- Reference temperature, incompressible/fixed-composition assumption, fixed dry mass, chemistry layout and actual original material identity remain separately bound. Equal cp values do not allow a foreign reference coordinate or modified mass to reuse an old energy identity.
- The source reader intentionally interprets finite floats by shortest decimal readout; the mass adapter intentionally converts binary64 floats to exact Fractions before calling it. Cache temperature keys must preserve this distinction, explicit K/degC units and boundary refusal. Retain exact integral, reversal/additivity, source node IDs, fit_error=None and material_qualified=False.

The smallest change with exactly the current operation-level integrity semantics is to cache only the parsed/deep-frozen pinned metadata and derived registry template after a successful content check. Every operation still re-reads/hashes current metadata/assets and resolves current allowed asset paths. This can save repeated JSON parsing/allocation or fixed path bookkeeping, but cannot be advertised as eliminating source I/O. Cache contents must never alias a returned mutable payload: registry_payload currently exposes nested authors/assets/material data from a newly parsed dict. A shared cached dict would let callers mutate later provenance without changing any file. Return fresh owned nested containers or keep an immutable internal representation and copy on export.

A cache that returns previously verified file bytes based only on path, Python id, mtime or size changes the trust contract. Same-length edits, restored mtimes, inode replacement, symlink retargeting, missing files and failed refreshes need explicit consideration. At minimum a metadata optimization would need current resolved containment, full stat identity including device/inode/size/mtime_ns/ctime_ns and pre/post-read stability checks before installing a cache entry, with content hashing after any change. Even then describe it as a filesystem-metadata cache under that filesystem assumption, not as SHA-reading all current bytes on every operation. Source/cache validation failure must not leave a valid cache flag. Do not introduce this silently as the old documented guarantee.

If measurement shows repeated source I/O dominates inside one calculation, an explicit bounded verification scope is a possible larger optimization: authenticate a private immutable source/asset snapshot at scope entry, run only nominal pure caloric arithmetic from that snapshot, then recheck source files and the original parameters before publishing the enclosing result. Keep default public cp/delta_h/registry semantics unchanged outside that scope. Do not turn a whole run, pause or restored process into an unlimited trust scope. Scope reuse must be restricted to the same live provider and declared inputs; nesting/concurrent contexts and use after exit must not leak authorization. An external callback mutation must be detected before publishing a successful result, and any work already attempted remains recorded. If both the calculation and exit verification fail, preserve the primary exception and record the secondary source-validation error. This changes the timing of intra-operation validation and therefore requires an explicit API/contract and corresponding tests; the existing test suite alone is not proof of equivalence.

`ArlabosseMassCaloric.binding()` and `_check()` currently call provider.cp, so eliminating only numerical Cp recomputation does not eliminate source I/O. SourceWetStorage.binding and BuiltSourceRun.check reach those guards repeatedly. Keep their cheap original collaborator/parameter checks on every relevant boundary even if source authentication is scoped. A constant cached binding digest cannot substitute for checking mutable runtime fields.

Minimum new regressions after an actual implementation: repeated normal calls retain exact values and fresh registry ownership; metadata edit/delete and asset edit/delete after a successful call are rejected; same-length/mtime-preserving replacement and symlink/path escape cannot hit an unrelated cache; mutate a previously returned nested registry and verify later output remains correct; reference/assumption/provider/mass mutation is still rejected before any unadmitted callback; concurrent providers with identical content under different roots do not share mutable state or hide one provider's changed file; a failed refresh cannot poison or validate a later call. For scoped authentication, add callback mutation, scope exit failure, primary-error preservation and closed-scope refusal cases. Preserve original rejected evidence; do not weaken tests to accommodate the optimization.

The completed passive parent profile contains no ArlabosseDryCaloric._source invocation. It establishes a saved-codec cost, not evidence that source-file caching solves the ordinary-stage timeout. Runtime hot-path profiling must establish the relevant savings before introducing the broader scope. No model, EOS, source read benchmark or test suite was run for this review.
