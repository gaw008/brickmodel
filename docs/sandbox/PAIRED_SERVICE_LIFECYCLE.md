# 共享参数族案例的服务生命周期

前一检查点已验证内核两次液水耗尽及独立逐步账本，见 [PAIRED_EVENT_COMPARISON.md](PAIRED_EVENT_COMPARISON.md)。本阶段使用同一物理案例验证实际服务的取消、恢复、封存与重放。

## 修复的恢复入口

v2 案例通过显式声明选择共享常数误差族，完整参数盒必须在实际算子构建后产生。原 `resume_run` 在构建前调用完整政策构造，因缺少算子而拒绝 v2。

现在入口先检查案例声明、全部标量政策及保存参数盒的严格结构；之后 `_run_event` 仍将新构建的完整政策（含实际盒身份）与父记录逐项比较，并执行原初态/来源/轨迹审计。前置结构检查不表示保存盒身份可信。新增回归明确验证：格式有效但内容不同的盒可以通过结构检查，却必须在调用积分器前被实际政策比较拒绝。

源测试与非 editable 安装测试各 43 项通过，安装验证 65 个模块与源码匹配。原始 RED 和独立审查保留。

## 实际运行

先用 `run_case` 运行原案例，以从启动起 60 秒的协作取消回调停止，不修改物理起终点或数值门槛。实际服务约 60.41 秒后返回 cancelled，保存 7 步、0 事件，最后接受时刻 0.5002315150882002s。累计积分用时 57.87845s、67 次评估；94 个归档文件通过 `read_run` 检查，来源与实现前后相同。

实际 `resume_run` 在约 301.42 秒完成原终点 0.50032s，30 步、2 事件、累计 596 次评估；原 7 步前缀逐项保持，累计积分用时 356.32439s，预算和政策没有重置。实际 `replay_run` 约 353.89 秒完成，30 步、2 事件、592 次评估；times_s、states、steps、events、corrections 五字段与续算逐项相同。三个服务目录通过封存校验，运行前后实现一致。三个监督会话均 exit 0，无活动原生进程。

完整结果七项实际来源查询无缺已登记资源；这不表示真实材料参数覆盖率为 100%。完整原始证据见 [paired-service-lifecycle-v1](research/paired-service-lifecycle-v1/README.md)。

## 缺终态来源查询修复

对上述取消目录调用 `trace_run(..., 'temperature_k')` 实际返回 `quantity_unavailable`：当前查询要求最终快照，而取消运行没有该快照。这一原始失败已保留。后续修复为合法查询仍返回来源图，但 value/result_pointer 为 null，明确 final_snapshot_unavailable；不代入初态或前缀。

修复后源码及非 editable 安装各 32 项测试通过，65 模块与源码匹配；对实际取消记录的七项查询均成功返回来源图和不可用说明，完整结果七项查询与修复前逐项相同，原封存字节未变。见 [partial-run-trace-v1](research/partial-run-trace-v1/README.md)。查询修复改变实现 SHA，因此原生生命周期证据仍绑定修复前冻结版本；本次查询验证不宣称重新执行了新版原生积分。

全部运行仅是明确制造参数、报告温度条件下的数值/软件验证，不补真实原污泥参数、联合温压保证、空间收敛或全烧成实验验证。
