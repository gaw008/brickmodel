# 独立阶段 Goal 顺序

2026-09-12 用户要求：每个 Goal 只承担一个阶段，验证与开发交替。[项目总规范](../BRICK_PHYSICS_PROJECT_SPEC.md)保留完整范围，不再作为自动完成全部任务的 Goal。

| 独立 Goal | 唯一任务 | 结束与准入 |
|---|---|---|
| **V0：验证已有成果** | 按[当前合同](../GOAL_BRICK_PHYSICS_SANDBOX.md)检查正误、证据与适用范围 | 完整审查报告和下一阶段准入；审查完成不等于全项通过。 |
| F0：必要修复/补证据 | 只处理 V0 一个明确阻塞或小组依赖阻塞 | 修复提交或新证据，不扩展新阶段功能，不自称验证通过。没有相应发现就不建立。 |
| V0R：再验证 | 检查 F0 是否解决原问题及影响旧结论 | 原反例保留，相关必需条件通过才开放下一开发；否则仍修复/验证。 |
| D1：下一阶段开发 | 在 V0/V0R 准入基础上只实现一个增量；连续干燥为候选，由审查决定范围 | 冻结目标、输入/输出与验收方案，交付代码、必要开发测试和可复现案例。实现完成与物理验证分开。 |
| V1：验证 D1 | 对 D1 冻结提交和受影响旧路径独立验证 | 四项检查、实际误差与准入结论；失败转具体修复及再验证。 |
| D2 / V2，依次推进 | 每次只开发一阶段，再验证该阶段 | 同一准入规则，不把全部剩余工作塞入单个 Goal。 |

验证不要求未采用且不被依赖的旧失败候选全部通过；也不能排除后续依赖的错误/未知项来制造准入。

以上是待创建的目标定义，不是已创建的应用 Goal，不新建任务、定时器或后台链。每次只启用一个具体 Goal，记录起点、交付与预算，结束不隐式继承无限续期授权。V0 沿用 120 分钟上限，其余在相应 Goal 建立时明确，不自行设置 token 数值预算。

截至本次调整，get_goal 仍返回暂停的旧完整建设目标。现有工具不能取消/编辑，create_goal 不能覆盖未完成目标。先由用户在应用中取消/移除或替换旧 Goal，再创建 V0 并核对实际内容；不得假报旧 Goal 完成、把其累计消耗移作 V0 成本，或只改文件就宣称面板已替换。
