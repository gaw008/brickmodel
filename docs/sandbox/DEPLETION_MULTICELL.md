# Sequential multicell depletion — pre-registration

Scope: two explicitly separated liquid-depletion events on one full conserved host, including shared liquid/gas/energy faces and a continuing reaction in the other cell. No new water/material properties are introduced. Simultaneous events remain outside this extension.

Before implementation, a manufactured numerical oracle fixes liquid amounts at (4.8e-6,7.2e-6) mol, gross evaporation 1e-3 mol/s per wet cell, shared liquid flux 2e-4 mol/s while both cells are wet, shared gas flux 5e-5 mol/s throughout, and shared energy flux 5 W. Independent events are t1=.004 s and t2=.008 s; the second is inside the original .01 s common-time horizon. An independent X→Y source 3e-4 mol/s in cell 1 continues through both events. Energy has cell 1 external power 3 W and cell 0 external power 2 W only after its own dry switch. End time=.012 s. Inventory columns are deliberately permuted as (Y, liquid, X, vapor).

Fixed gates: each event time error≤1e-8 s; every saved state's independent inventory≤1e-10 mol and U≤1e-7 J; exact Fraction reconstruction of full per-cell physical-face/source/work plus accepted paired/storage corrections≤the unchanged ordinary tolerances (1e-12 mol,1e-8 J). Water total≤1e-12 mol, X+Y≤1e-12 mol, nonnegative inventories, both events present in order, continued reaction at both terminal panels, and real common-time continuations before accepting each event. Resource limits: existing 5000 accepted trial panels,100 rejected trials,30 s. No old tolerance is relaxed.

Implementation intent: if another cell would deplete within the current preview horizon, shorten the common time to a strictly separated intermediate point. All prior coarse/fine previews are discarded and rebuilt at that same new time. Restart count is bounded; every speculative panel still consumes global resources. The outer accepted trajectory must then actually locate and commit the later event and continue to end. Ordinary post-event panels reevaluate the remaining wet candidates and use a conservative tau-based step cap so a changing rate is not silently stepped across. This is not a simultaneous-event or arbitrary stiff-system certificate.

Additional pre-implementation acceleration gate: after t1=.004 s, cell 1's gross sink is .0001+100*(t−.004)^2 mol/s; beforehand it is .0001 mol/s. Initial cell 1 liquid is 8e-7 mol, giving 1.2e-6 mol at t1 and the independent second root t2=.007 s. At t1 the frozen-rate prediction puts its event beyond the original horizon, so checking only the initial prediction is insufficient. Ordinary amount tolerances for this cubic integrated sink were declared at rel=1e-9/abs=1e-14 mol before execution; event gates remain unchanged. This case first failed at minimum_time_step. An intermediate fallback using the ordinary solver's last valid state still exhausted the existing 100-rejection budget. Both failure records are retained; no budget was raised.

## Implemented behavior and trace

The public `integrate_depletion` signature is unchanged. `DepletionRefinement` appends the optional `next_common_time_s` field after its pre-existing fields. A `common_time_horizon_reduced` record retains the old common time, proposed first-event time, new common time, level, evaluations and elapsed time. The new common time lies strictly between the first event and the remaining cell's predicted crossing, with more than `time_absolute_s` on either side. All previous coarse/fine states and comparisons are discarded; level zero starts again. At most `maximum_refinements` horizon restarts are allowed per accepted event, in addition to the existing bounded refinement levels and shared wall/panel/rejection limits.

The post-event continuation remains one full-system solve. If another wet cell remains, its actual complete evaluation is checked at every ordinary RK evaluation as well as accepted segment boundaries. This catches rate acceleration after the first mode switch. A required horizon change returns through the ordinary integrator's existing controlled error result before rethrowing the internal restart request, so previously evaluated trial work and accepted/rejected panels are counted even though the entire preview is discarded. An RK stage prediction is a numerical scheduling check, not a new material law or exact event-time proof. No source rate is clipped and no cell is integrated independently of its shared face.

After the first event's newly separated common-time comparison passes, its complete path is committed. The outer loop retains the second cell's wet mode and locates its event through the same ordinary/terminal/refinement procedure. It then actually continues both dry cells to the requested end. The tests require both accepted events, not merely avoidance of an invalid second crossing. Physical StepLedger entries and each event's paired/storage corrections remain separately reconstructible in the unchanged global Fraction prefix.

There are no new constitutive constants in production. The numerical oracle deliberately uses imposed manufactured face/source values and independent T=U/2 and pressure observations; it is not a water EOS or sludge kinetics dataset. Its layout permutation checks that liquid and vapor are addressed by their explicit indices rather than contiguous assumptions. The base two-event test independently verifies every saved inventory and energy state, both continuing reaction channels at both terminal panels, total water and X+Y, nonnegativity, and all per-cell physical/correction prefixes.

## Verification and remaining scope

Initial two tests failed with `second_event_in_common_time_preview`; the original output is retained in `research/depletion_multicell_initial_failure.json`. The acceleration failure is retained in `research/depletion_multicell_acceleration_failure.json`; the unsuccessful intermediate last-valid-state fallback is recorded in `research/depletion_multicell_intermediate_failure.json` and is not present in the final implementation. The final command was:

```sh
PYTHONPATH=src .venv/bin/python -m pytest tests/sandbox/test_depletion_multicell.py tests/sandbox/test_depletion_integration.py tests/sandbox/test_depletion_clock.py tests/sandbox/test_depletion_roundoff.py -q
```

Result: **36 passed in 2.12 s** (5 new multicell tests and 31 existing tests, unchanged). The new tests also verify that horizon restart clears the old comparisons, charges discarded work, and that a bounded resource failure preserves the previously accepted wet modes, states and correction prefix. Independent review and the root's source-gated coupled-water experiment have their own evidence; these manufactured tests do not imply their outcomes.

This extension validates the stated two-cell sequential examples, including the accelerating second sink. Simultaneous, unseparated, chattering or infinitely accumulating events remain unsupported; severe stiffness or unknown constitutive domains can still produce explicit failures. Horizon adaptation is a bounded numerical scheduling strategy, not proof that arbitrary multi-event topology is resolved. Ordinary integration accuracy remains independently controlled; as shown in the earlier nonlinear probe, small local event indicators cannot certify all earlier wet-trajectory error. Program nodes continue to bound every horizon and cannot be silently merged with events.
