## 4. 不可编造的物理与证据合同

允许有出处、适用范围明确的物理近似；不允许用语言模型猜测值冒充材料事实。“论文存在”“引用正确”“代码守恒”和“适用于本材料”是不同要求，必须分别检查。

将每一项输入、模型关系或数值设置分类：

- `physical_law_or_constant`：守恒律、量纲关系、可核查的物理常数。
- `measured_public_data`：有明确材料身份与条件的公开实测。
- `literature_constitutive_model`：有出处和适用条件的本构/经验关系；不能称为普适定律。
- `derived_from_evidence`：从上述来源按记录的公式、拟合或转换得到。
- `virtual_design_choice`：明确由用户或实验设计指定的配比、几何、炉温程序等，不冒充实测。
- `numerical_policy`：网格、时间步、求解器容差等数值选择，有选择理由和收敛证据。
- `manufactured_test_fixture`：仅用于解析/制造解和软件测试的人工构造，不进入材料结论。
- `unknown`：缺乏足够依据，值为 null 或受控缺项，不能静默变为 0、平均值或默认值。

虚拟实验可以设置尚未在现实中执行的条件，但要检查元素/质量比例、物性关联、几何及设备边界是否自洽。不能凭空设置未知材料的活化能、黏度、强度、临界压力或“安全分数”。设计决策范围也必须区分“有现实可实现性依据”和“纯探索域”。

每个真正参与材料预测的方程及关键参数，必须记录：

- 稳定 ID、名称、符号、数值/函数、单位和干基/湿基/摩尔基/体积基。
- 来源类型、作者/机构、标题、年份/版本、DOI 或稳定 URL。
- 具体定位：页码、公式号、表格、图号、补充数据字段或工作簿/工作表/单元格。
- 实际阅读状态、获取日期、允许保存的原始文件路径与 SHA-256、许可及再分发条件。
- 原材料类别、组成/矿物相、粒径、制样、气氛、温压、升温速率、几何与测试方法。
- 原值、单位转换、归一化、插值、数字化或拟合过程，及对应代码与上游 ID。
- 适用域、误差/不确定性依据、参数相关性、外推规则、已知争议及排除原因。
- 与当前材料域的匹配判断、判断依据，以及允许支持哪些输出。

形成可机器检查的来源注册表、参数包、方程注册表和来源依赖图。图上必须能从任意结果追到“使用的模型与参数 → 派生过程 → 原始证据位置”；只列参考文献或网页首页不算完成溯源。

只有摘要或检索片段时，不能声称已核读正文中的数值。网页不可访问时寻找合法开放版本；仍无法核实就保留缺项。图像数字化必须保留原图位置、数字化方法和读图误差。软件文档证明软件功能，不自动证明材料参数有效。

所有实际用于证据支持预测的物理参数，来源链覆盖率必须为 100%，同时单独报告适用性和外部验证覆盖率。不能把虚拟设计值、测试值或只有背景文献的参数计为实测覆盖。关键依赖未知时，受影响输出必须拒绝计算或降级为明确的探索结果。

探索结果必须与有证据约束的研究结果分开存储、显示和排名。现有 synthetic 包不得通过改标签升级为真实材料包。没有依据的不确定性区间同样属于编造；主观区间只能用于明确的探索，不能叫经验置信区间。

## 5. 公开资料获取与材料域

在开发早期建立来源覆盖矩阵，按必需机制、参数、适用材料和验证数据分组。先找能支撑最小完整材料域的证据，而不是无目的堆论文数量。

可从以下入口开始；这些只是检索入口，不表示其内容已经适用于本模型：

- NIST Chemistry WebBook： https://webbook.nist.gov/chemistry/
- NIST-JANAF： https://janaf.nist.gov/
- Cantera 官方热化学、反应与输运文档： https://cantera.org/
- pycalphad 官方文档及符合组成域的可用数据库： https://pycalphad.org/
- 现有 DTU 数据、原始研究论文及其补充材料。
- 原污泥在明确气氛下的多速率 TG/DSC、气体分析与残炭数据。
- 黏土/污泥体系的热膨胀、收缩、相组成、孔隙、渗透率、黏度及力学公开研究。

遵守以下材料建模要求：

1. 原污泥、焚烧灰、工业污泥、黏土、页岩和煤矸石分组；跨域借用参数需单独论证。
2. 元素组成、氧化物分析、矿物相、无定形相和 LOI 分开；不能把 XRF 唯一反演成矿物相。
3. 热解、残炭氧化和无机分解分别寻找证据；成套动力学参数必须保留对应反应模型、气氛、温区和联合不确定性，不能从不同论文挑最有利的 A、E 拼接。
4. 纯物质热化学数据不足以自动定义多元氧化物液相；热力学求解器不等于具备所需数据库。平衡液相分数也不等于实际有限速率液相、黏度或烧结速度。
5. 决策变量优先是现实可操作的混配、脱水、粒径处理和炉温/气氛程序。密度、导热、比热、孔隙和渗透应由材料身份及有证据的关系共同约束，不能各自独立优化到有利极值。
6. 公共数据用于拟合时，按独立材料/批次/研究或热历史划分验证集合；同一批试件不能伪装成独立外部验证。来源条件不全的终态数据只能支持相应的有限结论。

若关键资料找不到，记录实际检索、可替代来源、可继续的工作及缺项影响。不要要求我先积累几个月本厂数据，也不要因此制造参数。可以提出最小补充证据需求，但完整材料模型尚未满足的必需项仍保持未完成。

## 6. 必须实现的物理内核

先写版本化的“虚拟世界定义”：状态量、控制体、材料/空间尺度、初始与边界条件、方程、构成关系、耦合图、有效域和忽略项。所有求解器、CLI、界面和优化器共享这一份定义。

### 6.1 材料与初始砖坯

定义固体、水和气体库存、材料相/反应组分、初始开放/闭合孔隙、干湿基、几何和成型后初态。混料守恒，比例和基准明确；成型加水与原料自带水不重复计算。采用给定湿坯作为起点，若不模拟挤出/压制，也要说明初始状态的依据。

### 6.2 传热、干燥与反应能量

至少求解一维内部温度分布，包含导热、表面对流和辐射、液态水/水蒸气迁移与蒸发、反应吸放热。干燥所需的有效输运或毛细本构要有来源和适用域；不能仅用一个无出处 Arrhenius 脱水常数替代全部湿坯干燥。

建立覆盖所建模系统的能量平衡，包含随组成/温度变化的储能和进出物流携带的焓；明确焓基准、相变与反应热的处理，防止重复计热。必要的机械功项应计入或通过尺度分析说明可忽略。给定炉温不能直接成为砖芯温度，简化温度 ODE 的恒等式不能标记为完整能量守恒。

### 6.3 多步化学与有限供氧

根据选定材料的证据实现自由水、有关矿物脱羟/碳酸盐分解、有机物热解及残炭氧化等必需路径。每条活跃路径提供元素计量、产物分配、速率关系和热效应来源。伪组分必须有明确组成及适用依据。

氧气有实际库存、边界流入和局部输运约束；氧化不能消耗不存在的氧气。无氧条件不强行关闭本应存在的热解路径。与目标过程相关却缺失的挥发物不能按零排放处理；简化组分集合必须列出遗漏对质量、能量和适用域的影响。

### 6.4 气体、水分、压力与孔隙输运

对建模气体使用一致的摩尔/质量库存、分压/总压、孔内体积和流入/流出账本；包括必要的载气，而不把产气组分之和当作完整气相。明确状态方程以及适用的温压条件。

根据尺度分析与资料选择扩散、压力驱动流动及必要的多孔介质输运关系。不能仅用理想气体公式算压力、再让输运完全不受压力影响却称为完整耦合。简化必须经过适用性论证。

### 6.5 烧结、相变化与几何演化

实现有来源的致密化/收缩及开放孔隙、连通性、渗透率演化；可比较多种有依据的模型形式。涉及液相/黏度时核实数据库或模型覆盖，禁止沿用任意 sigmoid 后改称真实热力学结果。

同一质量、体积和几何定义用于密度、孔隙、气体浓度、表面积与传递距离。选择参考构形或当前构形并一致处理变形；不能同时改变几何又漏掉对应的库存/通量换算。孔道显著封闭后，采用有依据的闭孔状态处理，或者明确在适用边界停止；不能把孔隙截到一个小正数继续伪造完整烧成结果。

### 6.6 冷却、应力与产品性能

模拟冷却温度和收缩过程，在已有热弹性/黏弹性等材料证据与边界约束下计算应力。若某相变对选定材料域显著，按证据纳入或说明不能覆盖的条件。

密度、吸水率、强度、开裂、鼓胀、翘曲需分别声明依据。没有力学本构、失效阈值、测试尺度与验证证据，不能把孔隙率或温差公式输出称为真实抗压强度或破坏概率。优先交付可解释的状态量、应力与证据支持的指标；缺乏支持的产品判定为 unknown，不参与“合格”排名。

### 6.7 最小耦合要求

温度影响反应/输运/烧结；反应影响固气库存和能量；水分迁移影响能量与气相；烧结影响孔隙/几何/渗透；气体及压力反馈到输运。所有交换项在相关方使用一致的符号、单位和积分权重。

不能用数个独立脚本各画一张图来冒充耦合。通过集成测试证明打开某项耦合会改变相应状态与账本，并用适用的极限解验证变化。

## 7. 虚拟实验与逐代搜索

实现可配置的实验定义、运行、恢复和比较：

“选择有依据的材料包 → 生成物理自洽的候选 → 全过程求解 → 数值与来源检查 → 计算有依据的目标和约束 → 比较不同假设下的表现 → 生成下一代”。

要求：

- 每次搜索冻结模拟器、材料/来源包、参数推导、目标/约束和随机种子。模型升级建立新实验，不混用旧分数。
- 先用实验设计、全局敏感性分析和较小候选集识别关键因素，再根据耗时扩展搜索。允许多目标/Pareto，不预设必须存在优胜者或全局最优解。
- 至少完成一次有后代选择过程的多代搜索，保留每代候选、父代关系、实际变化、失败、评估和停止理由。预先设定计算预算和停滞标准，不能为展示进化而编造代际改善。
- 比较温差、局部残碳、气体排出、致密化/尺寸变化及有支持的力学指标。单位砖体净热输入不自动等于实际窑炉燃料耗能。
- 主耗氧结束、主产气结束、局部残碳事件和孔道连通性变化可作为解释指标；事件定义、阈值与时间分辨率明确，不把它们单独当作产品合格充分条件。
- 分开材料变异、参数认识不足、模型形式差异与数值误差。没有统计依据的情景占比不能称为实际成功概率。
- 数值失败、证据不足、超出适用域、尚未达到事件、违反有依据的物理约束是不同状态。搜索可以暂时不选失败候选，但不能把计算失败解释为材料不可行。
- 对搜索选出的候选重新用物理求解器和独立验证情景评估，检查是否利用了边界、离散误差或模型缺陷。
- 可选的机器学习替代模型只用于加速已验证域内的求解，必须单独验证并保留物理复算。模拟结果不能成为证明同一模拟器正确的外部证据。

## 8. 验证体系与禁止通过的捷径

在观察最终结果之前，登记验证案例、比较量、单位、归一化尺度、绝对/相对容差及科学理由。求解器容差、结果比较门槛和实验误差是不同概念。修改门槛须有独立理由，保存前后结果，不能仅因失败而放宽。

本节检查逐阶段执行，按第 0.5 节与 `sandbox/VALIDATION_PLAN.md` 分别判定四项准确性条件；不能把现实对照统一推迟到所有软件完成之后。

### A. 代码与数值验证

- 单位、比例、计量配平、材料有效域和来源完整性。
- 惰性传热、无反应扩散、密闭反应、有限氧上界、开放/封闭边界及适当的蒸发/变形极限案例。
- 独立解析解、半解析解或制造解；参考实现不能直接调用被测试求解器得到“真值”。
- 空间与时间收敛、正性/有界性、刚性/失败处理、边界条件与耦合交换一致性。
- 独立重算质量、元素、所定义系统能量和边界通量账本；全流程与分阶段都要检查，不能只看起终点抵消后的残差。
- 禁止通过无记录 clip、归一化、重置库存、篡改初值或隐蔽平滑来制造守恒/收敛。必要的数值修正必须说明理论依据并量化影响。

### B. 对现实证据的验证

- 至少覆盖干燥/传热、原污泥反应或残碳、烧结/收缩三个必需机制组的公开实测对照。
- 独立报告每个对照中的材料、气氛、几何、热历史、拟合/未拟合身份、误差和不足，不使用一个总体分数掩盖某个模块失败。
- 至少留出未用于调参的实验条件做预测检查；按实际独立层级划分，避免重复件泄漏。
- 至少尝试并记录有成对材料与烧成条件的耦合过程对照。若只有分模块证据，必须明确“整块砖耦合预测尚未获外部验证”，不能升级成工厂可信模型。
- 数据不能检验的输出保持未验证；公开资料中的实验验证不自动覆盖本厂原料或设备。

### C. 集成与使用验证

- 从干净、依赖锁定的环境完成数据准备、单例求解、来源查询、批量比较、多代搜索、导出和重放。
- 至少实测当前开发平台；对宣称支持的其他平台提供真实验证。无法运行的平台写为未验证，不能以文档代替测试。
- CLI、Python 接口和界面必须调用同一内核，同一输入结果一致。
- 实际打开本地界面验证编辑、运行、取消、失败显示、场景比较、曲线/空间剖面和来源跳转。
- 检查非有限输入、缺失关键参数、单位不符、域外材料、不可访问来源、断点恢复以及失败候选处理。

Hash 证明文件一致性，不证明物理正确；同一模型重跑一致不证明现实正确；子代理意见也不等于科学外部验证。这三类不能互相替代。

至少交付以下内容；可以沿用已有同等结构，但必须有清晰的映射与实际文件：

- `docs/sandbox/GOAL_STATUS.md`：持续进度与恢复入口。

- `docs/sandbox/EQUATION_CODE_MAP.md`：方程/参数到实现及测试的双向定位。
- `docs/sandbox/VALIDATION_PLAN.md` 与实际 `VALIDATION_REPORT.md`。
- `docs/sandbox/SUPPORTED_DOMAIN.md`：哪些材料、条件、尺度和输出已获何种证据支持。
- `docs/sandbox/KNOWN_GAPS.md`：真实缺项、影响范围和最小下一步证据需求。

## 10. 推荐执行次序

以下 G0–G5 是完整交付的依赖地图，不是当前恢复时重新执行的清单。当前具体顺序及预算以第 0 节为准：D1 连续干燥 → 指定缺口的材料证据关卡 → 同材料全周期耦合与验证 → 多代实验及使用功能；不得以原顺序绕过窗口停止条件。

G0：核对仓库与历史失败，完成证据覆盖和关键可行性检查，建立最小世界定义及验收矩阵。

G1：完成来源/单位/材料系统和一组实际核读的材料参数；为缺项建立运行时阻断。同步准备独立验证数据。

G2：修复或替换需要继承的 B2 失败路径，实现守恒的热湿与反应—供氧—排气耦合，完成对应数值和公开实验验证。

G3：接入有依据的烧结、孔隙/几何、压力反馈与冷却应力，实现单块砖全周期。完成集成收敛与能量验证，查明整体验证覆盖。

G4：完成不确定性、敏感性、批量实验和多代搜索；复算候选，检查候选排序对合理模型变化的稳定性。

G5：完成 CLI/界面、结果溯源和干净环境重现；审查需求覆盖，修复实际缺陷，整理可操作交付。

同一已授权窗口内的必要步骤无需逐项批准。遇到来源缺口时，只继续当前窗口内不依赖该缺口的实现与验证；发现核心材料关系无法证实时，明确核心阻塞，不能扩展无关任务、无限检索或悄悄缩减目标以报成功。新窗口按第 0 节进入。

## 11. 完成与停止条件

分别记录三个维度，不得合成一个含糊的 PASS：

1. `software_status`：必需模块是否实际实现、耦合、能运行、可复现。
2. `scientific_status`：方程和参数是否有证据、适用性如何、哪些预测通过独立实验检查。
3. `deployment_status`：本 Goal 默认只有离线研究；不表示工厂投产、产品合规或设备控制批准。

只有以下条件全部成立，才可将此 Goal 标记为完成：

- 第 1 节规定的完整流程和使用功能已实际实现，必需机制无空壳、TODO 替代、硬编码结果或 synthetic 参数偷换。
- 至少一个明确包含原污泥的材料域具有完整、可审查的关键参数/方程来源与适用性论证，并成功运行全周期案例。
- 质量、元素、所定义系统的完整能量与数值收敛验证通过；失败不能通过删测试、改意义或放宽门槛消失。
- 第 8 节三个机制组具有实际公开实验对照及预先登记的误差结论；至少有未参与调参条件的预测检查。不能只有模型自测。
- 全周期案例和多代实验实际执行，结果能够逐层追到证据；未知指标不被用于虚假的合格/最优声明。
- 全部必需要求在验收矩阵中有实际证据，CLI/界面与干净环境流程实际验证，关键代码/物理审查问题已关闭。
- 各必需物理阶段满足第 0.5 节的逐阶段准确性条件，结论限定于实际验证域；任一关键机制或必需输出仍未验证，不得汇总为完整模型准确。
- 最终报告准确区分已获分模块验证、已获耦合验证和未验证的范围。没有整体现实验证时，不得称为“已经准确复现真实砖厂”。

缺少关键公开材料证据、必需模块无法闭合、关键验证未通过，均属于未完成，不能仅因为软件能画曲线就把 Goal 标记为完成。在当前窗口范围和预算内完成可独立推进的必要工作，再按运行环境的 Goal 阻塞规则报告：缺什么、已经尝试什么、影响什么、需要什么最小外部变化。`blocked` 只在工具规定的连续阻塞条件满足时使用；预算耗尽、阶段结束或用户暂停本身均不满足该条件，也不等于完成。不要无限重复同一失败尝试。

最终交付用中文说明：如何启动、如何跑一块砖、如何迭代下一代、如何追查一个结果的来源、实际验证了什么、仍有哪些不能推断的事情，以及 Git 提交和产物位置。

用户启动或恢复后，按第 0 节读取现有恢复入口，记录当前窗口并推进 D1 的实现与验收；不要重建已有矩阵。只请求调整 Goal 时完成合同更新和核查，不顺带启动计算。到达窗口停止条件时如实交付，完整 Goal 仍只有满足本节全部条件才可完成。
